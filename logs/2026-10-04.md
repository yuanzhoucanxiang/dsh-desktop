## 修复：scheme 模式下主界面永久「重新连接中」（0.1.45 埋下的 mux 断流）

用户报安装版（0.1.47）侧栏底部红色「重新连接中…」永不消失。顺藤摸瓜挖出一个影响**所有 scheme 模式构建**的断流 bug。

- **病灶链路**（全程实锤，无推测）：
  1. 页面（`dsh-app://app`）的全量数据走 remote.mux WebSocket：前端 `remoteStreamUrl()` 拿 `document.baseURI`（=`dsh-app://app/`）拼出 mux 地址，外壳注入的 WS 兜底（`makeWebSocketShim`）把它改写成 `ws://127.0.0.1:<port>/api/remote.mux` 让页面直连内核。
  2. Chromium 给 WS 握手带上 `Origin: dsh-app://app`（standard scheme 的必然行为；页面脚本受同源策略**无法**自改 Origin）。
  3. 内核 `isTrustedApiRequest` 栅栏：有 Origin 时要求其 host == Host 头——`app ≠ 127.0.0.1:<port>` → **恒 403**。且跨站 WS 连 Cookie 都发不出来（就算过栅栏也 401）。
  4. `ConnectionController` 指数退避重连 → 指示器永远「重新连接中」。
  - 聊天等核心功能之所以照常：它们走外壳 HTTP 转发（`forwardToKernel` 会剥 Origin、代持 cookie，天然合规）。**只有 WS 直连这条路漏了。**
- **取证**（零依赖 CDP 脚本，工作区根 `verify-mux-handshake.mjs`）：预览实例挂 `--remote-debugging-port`，抓 `Network.webSocketWillSendHandshakeRequest`——修复前 5 次握手全部 `403`（控制台风报 `Unexpected response code: 403`）、每 6–8s 重试一轮；仓库预览与用户安装版**同症**，排除"用户环境坏了"。
- **修法**（`main.js`，仅 scheme 模式挂）：`session.defaultSession.webRequest.onBeforeSendHeaders` 拦指向内核端口的 ws(s) 握手——剥 `Origin`/`Sec-Fetch-*`、代注 `state.webCookie`（内核栅栏对无 Origin 的回环 Host 放行，与 `forwardToKernel` 同一口径）。外壳本来就代持这份 cookie，此处只是把它补进页面直连的 WS 握手。
- **结果**：修复后预览实例 mux 一次握手 `101` 长连（挂监听刷新页面实测），「重新连接中」消失，会话列表/模型选择器/工作区全部加载。顺带治好同病灶的插件直连 WS（better-sidebar 终端/文件监听——shim 注释里说的"官方壳上本就是坏的"，现在这条路上 Origin 也被剥了）。
- **坑 / 备注**：
  1. 诊断中一度被 netstat 误导：页面对 13058「零连接」其实是采样时机问题——TIME_WAIT 堆积正是"连上→403→断开"的烟囱；后来 200ms 密采抓到 network 进程的两条 ESTABLISHED。
  2. Ctrl+Shift+I / F12 在安装版被禁（菜单「开发者工具」与 F12 都只在 DEV 下挂），页面侧取证只能走 `--remote-debugging-port`。
  3. 内核运行时仓库与安装版同为 0.1.7-rc.2（09-25），栅栏不是新引入的——是 shell 0.1.45 换 scheme 架构时与它撞上的。
- **改动文件**：`main.js`、`CHANGELOG.md`、`logs/2026-10-04.md`；工作区根新增 `verify-mux-handshake.mjs` / `verify-mux-101.mjs` / `verify-preview-state.mjs`（取证脚本）。
- **待办**：安装版要带上修复需重新 `npm run dist` 打包安装（构建输出按约定放 %TEMP%）；打包前注意工作树里还有写作模式的一批未提交改动（与本案无关），别混进安装包。

## 作品档案 wiki 站点化：一页长滚动 → 多页站点（「每个人物和内容都有对应的页面」）

用户设想：档案应像内置 wiki 网站，每个人物和内容都有对应页面。本轮把 `route=wiki` 从单页长滚动改为多页站点；**导出 HTML 出口保持单文件快照不动**（两个出口分工自此明确：导出 = 打印/分享快照，wiki 窗口 = 翻阅站点）。

- **页面结构**（`page` 参数，页 id 白名单 `index|settings|progress|ledger|docs|doc-N|doc-N-sK|ch-N`）：
  1. 首页 = 入口：前提 + 码字统计/14 天柱 + 四区入口卡（设定/进度/时间与伏笔/资料，各带计数）+ 设定标题速览（链到设定页对应卡片锚点）+ 人物速览（人物组资料的节页直达）+ 章节导读（前 8 章 + 全部链接）——不再堆全部内容。
  2. 设定/进度/时间与伏笔页：直接复用 `archive-html.js` 的三个 section（单一事实源，导出页输出逐字节不变）；进度页章节名变成章页链接（`progressSection` 新增可选 `nav.chapterHref`，不传时纯文字、导出不受影响）。
  3. 资料索引页：按组列篇目卡（标签 + 一句摘录 + 小节数/rel，卡上带 `data-rel` 供门禁定位）。
  4. 篇目页（doc-N）：篇内 `##`/`###` 小节 ≥2 → 导语 + 节卡（正文不在这里堆叠，卡片只带截断 60 字摘录）；不足两节 → 整篇铺开（复用抽出的 `docArticle`，与导出页资料区同一形态，含篇内小目录）。
  5. 节页（doc-N-sK）：「每个人物一页」的落地——面包屑 + 节正文 + 节间上下页 + 返回篇目。
  6. 章页（ch-N）：当版正文一页，按需现读注入（读不到如实说明，不拿旧稿冒充）；**散文分段渲染不走 renderMarkdown 的空标签过滤**——手稿里「他说：」这种行绝不能被吞，空标签过滤是给资料模板降噪的。
  7. 回落纪律：page 形状非法 → 首页；节号越界 → 篇目页；篇号越界 → 资料索引；章号越界 → 进度页。
- **工程口径**：`assembleArchiveModel` 拆出 `buildArchiveModel`（返回 model；导出口 = model → `renderArchiveHtml` 薄壳，wiki 出口 = model → `renderWikiSite`）。站点零 IO（章节正文由路由注入）、零脚本（CSP 不动）、链接全部同源相对 GET。`[[文稿名]]` 解析口径不变（buildRefResolver），目标从页内锚点换成站内页链接——`inlineMarks` 新增 `SAFE_PAGE` 白名单形态（只收 host 形态 `?route=wiki&amp;path=…&amp;page=…`，未转义的 `&`、裸引号、`javascript:` 一律退回标注；导出页解析器不产出这种链接，为惰性兜底）。`CSS`/`dayBars`/`docArticle`/`isLabelOnly`/`inline` 从 archive-html 导出复用。
- **链接纪律**：站内所有 `<a>` 一律 class 在 href 前——门禁用 `<a href="?route=wiki` 精确匹配切换条自己的链接，翻页链接不混进死链断言组。
- **验收**：纯函数 23 → 32 项（E01–E09）；`verify:writing-archive` 11/11b/13 段改写（内容断言落到子页、切换链接抓 path 到 `&` 为止、末段真点导航：顶条换区→资料索引→篇目→节页→章页→切换条换作品）14 段 PASS；架构/构建/plugin-sync 门禁过；`verify:writing-quick` 全链 **QUICK_EXIT=0**（600 行 PASS/OK，0 非零）。
- **改动文件**：`plugin/writing-mode/lib/archive-html.js`（导出 CSS/节函数/部件 + SAFE_PAGE）、`plugin/writing-mode/lib/archive-site.js`（新）、`plugin/writing-mode/index.js`（buildArchiveModel 拆分 + wiki page 参数 + 章页现读）、`plugin/writing-mode/runtime-manifest.json`（+archive-site.js）、`plugin/writing-mode/test/archive-html.mjs`（+E01–E09）、`scripts/verify-writing-archive.cjs`（11/11b/13 段）、`plugin/writing-mode/CONTRACT.md`（wiki 行）、`docs/writing-mode-plan.md`（+§23）、CHANGELOG、本日志。
