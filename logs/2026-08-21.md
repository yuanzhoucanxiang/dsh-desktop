### 1. 注入 UI 跟随外壳皮肤（侧边栏 + 断连浮层）

- **做法**：不去逐条改样式，而是在 `<html>` 打一个 `data-dsh-skin` 标记，把注入 UI 用到的 `--dsw-alias-*`
  设计令牌**重定义在外壳自己的根元素上**（`#dsh-review-root` / `#dsh-shell-kernel-overlay`）。
  自定义属性只向下继承 → 一次覆盖 90 处配色，且**绝不外泄到内核页面**。
  - `deep`（默认）：一个字都不覆盖，侧边栏继续跟随内核主题（原行为零回归）
  - `seascape`：覆盖成单色银盐；diff 用「调过色的银盐」——加为冷调 `#a9c2b6`、删为暖调 `#c9adad`，够分辨又不跳出单色
- **改动文件**：`preload.js`（`applySkin` + `SKIN_TOKENS` + `shell:theme` 订阅；浮层配色改用变量）
- **新增回归**：`npm run sidebar-skin-check`（`sidebar-skin-check.js`，自带内核页面桩）——**15 项全过**，
  其中最关键两项：`no leak: kernel-owned element unchanged`、`no leak: kernel page background unchanged`

### 4. 第一批可用性迭代（全部外壳层，内核零修改）

- **原生应用菜单 + accelerator**（`buildAppMenu`）：菜单栏默认隐藏（Alt 唤出），快捷键始终生效 ——
  用最低成本让每个能力"可发现、可键盘直达"。分组：会话 / 编辑 / 视图 / 审阅 / 内核 / 皮肤 / 帮助。
  `Ctrl+Shift+B` 切审阅侧栏、`Ctrl+Shift+N` 新窗口、`Ctrl+Shift+K` 重启内核、`Ctrl+Shift+O` 工作目录、
  `Ctrl+/` 快捷键一览、`Ctrl+R`/`Ctrl+Shift+F5`/缩放/全屏走标准 role。
  **约定**：命令进菜单，设置留托盘，两边不混。
- **多窗口**（`openExtraWindow`）：同一内核开多个窗口并行看会话；随皮肤换底色。
- **全局唤起热键**（`applyGlobalHotkey`，默认 `Control+Alt+D`）：按一次唤起、再按一次收起；托盘可开关。
- **回合完成通知**（`startTurnWatcher`）：读审阅事件流（`review-events.ndjson`）按字节增量解析 `turn-end`，
  **仅在主窗口失焦时**弹系统通知，点击回到工作区并打开审阅面板。首次扫描只"预热"不补课式轰炸；无审阅流时静默。
- **深链接** `dsh://open|review|restart`：仅打包版注册协议（开发/冒烟不写注册表，免污染真实环境）。
- **顺带修的测试盲区**：`refreshMenus()` 在冒烟下也**构建**菜单（只是不挂上去），
  这样非法 role/accelerator 会在冒烟里就炸出来，而不是只在真机崩。

### 6. A 案第一步：审阅 git 层落地（后端 + 单测，UI 待下一轮）

- **抽成纯 Node 模块** `lib/git-review.js`（`createGitReview(getCwd)`），三条理由写在文件头：
  ① 能用 `node lib/git-review.test.js` 秒级单测（真仓库真 git，不起 Electron）；
  ② **逐块补丁"现读现切"**——渲染侧只传 `{文件, 第几块}`，补丁在主进程重新从 `git diff` 切出来，
     避免拿旧补丁打到新文件上（脏了就 `git apply` 干净失败）；
  ③ 万一以后走生态原生路线（做成内核插件），这一层可整块搬走。
- **能力**：`stage` / `unstage` / `revertHunk` / `revertFile` / `commit` / `push`，
  以及给面板用的 `changes()`（新增 `diffUnstaged`、`diffStaged`、`hunksUnstaged`、`hunksStaged`、
  `branch`、`hasRemote`、`stagedCount`，同时**保留旧的 `diff` 字段**，老 UI 与老测试零回归）。
  实现细节：暂存块 = `git apply --cached`，取消暂存块 = `git apply --cached --reverse`，
  丢弃块 = `git apply --reverse`；整文件取消暂存优先 `reset HEAD`，无 HEAD（还没有提交）时退 `rm --cached`。
- **分寸（照 Codex 的手感）**：可逆的（暂存/取消暂存）**不打扰**；破坏性的（丢弃这一块）与对外发布的（推送）
  **必须二次确认**；提交前会先拒绝"空暂存区/空信息"。
- **单测 33 项全过**（`npm run git-review-test` → `GIT_REVIEW_OK`），最关键一条：
  `第 0 块仍在（LINE ONE 保留）` —— 证明逐块丢弃**只丢那一块**，不会把整文件还原掉。
  另外覆盖了：未跟踪文件、已删除文件、无远端 push 的人话报错、越界块序号、非仓库目录。
- `main.js` 只保留外壳职责（确认框 + IPC + 日志），`package.json` 的 `build.files` 已补 `lib/git-review.js`
  （否则打包版会漏掉这个模块 —— 这类"打包才炸"的坑必须当场堵）。
- 回归：`GIT_REVIEW_OK` + `sidebar-test` + `sidebar-layout-test` + `sidebar-skin-check` + `smoke` 全绿。
- **下一轮**：面板 UI（未暂存/已暂存分档、逐块按钮、提交框 + 推送）、以及"检测到 better-sidebar 就让位"。

### 7. 生态报告落盘 + 内置插件"脆弱选择器"自检（把隐患变成会响的警报）

- **`docs/dsh-ecosystem.md`**（103 行，子代理落盘）：DSH 本体/桌面壳/插件/UI 约定/插件 vs 外壳分工/查不到的东西六节，
  star 与版本均为 API 直查、含「已验证/推断/未验证」标注。两条对我们最有用的结论：
  1. **官方 UI 扩展点是 Slots，不是路由**，且 SKILL.md 明令禁止硬编码私有选择器；
  2. 「插件吐数据/开端点 + 外壳原生渲染」正是我们 `review-bridge` 的模式，被判定为可持续路线 ——
     **不要用 DOM 注入去跟 web UI 抢布局**（这也正好印证了用户选的 A 案）。
- **报告点名了我们自己的技术债**：内置 `plugin/dialog-optimize/client.js` 混用了
  编译后 hash 类名（`.gdEzaW_bubble:422`、`.p-xYUq_timeStart:428`、`.Md3f7G_older:460`、`.p-xYUq_actions:583`）
  + MutationObserver/rAF，内核前端一改样式就会**静默失效**。
- **我没有照抄结论，而是去证伪**：拿 rc.7（仓库 runtime）与 rc.6（已安装应用 runtime）逐个对照 ——
  **四个 hash 类名在两个版本里都还在**。所以这是**潜在**风险，不是当前故障（CSS module 的 hash 只在该组件样式变动时才变）。
- **于是把它做成会响的警报**：新增 `plugin-selector-check.js`（`npm run selector-check`）——
  从 `client.js` **自动抽取**它依赖的选择器，逐个到内核前端 bundle 里找，找不到就 exit 1 并点名是哪个、影响哪个功能。
  - 抽取时会**剔除插件自己写上去的属性**（`setAttribute/removeAttribute` 写过的），
    否则会误报 —— 首跑就抓到一个假阳性 `data-pinned`（那是它给自己 `.dshReplyRow` 打的标记），已修。
  - 现在监控 **4 个 hash 类名 + 7 个 data 属性**；rc.6 与 rc.7 均 `SELECTOR_CHECK_OK`。
  - **已挂成打包门禁**：`npm run dist` = `selector-check && build.ps1` —— 选择器失效时**宁可打不出包，也不发一个功能静默失效的版本**。
    没有 `runtime/` 时脚本 exit 0（干净检出不误报）。
- 顺带记一条环境坑：本机 `pwsh` 走的是 Windows PowerShell 5.1 语义，**不支持 `if` 作为表达式**内联进字符串格式化。

### 8. A 案收尾：面板 UI 接上 + 共存让位（本轮完成）

- **面板 UI（`preload.js` 的 `renderGit` 重写）**：
  - 展开文件后**按 hunk 分档**：「已暂存 · N 块（提交时会带上）」在上、「未暂存 · N 块」在下；
    每块一条操作条（`第 N/M 块 · @@ …`）+ 按钮：未暂存给 **暂存这块 / 丢弃这块**，已暂存给 **取消暂存这块**
  - 文件级补 **暂存 / 取消暂存**（原有的 还原/删除 保留）
  - 底部**提交条**：信息输入 + 提交（暂存区为空则禁用）+ 推送（无远端则禁用），
    元信息显示「已暂存 N 个文件 · 分支 · 无远端」
  - 客户端切 hunk 的规则**与主进程 `lib/git-review.js` 的 `splitDiff` 完全一致**（从第一个 `@@` 起、
    遇 `@@` 起新块、遇 `diff --git ` 停）—— 这是块编号能对齐的前提，已在代码注释里写明这条耦合
  - 新样式全部走 `--dsw-alias-*` 令牌 → **海景皮肤自动覆盖，无需额外适配**
- **共存让位（`dsh-coexist`）**：检测到内核侧右侧栏插件（`better-sidebar` / `dsh-workbench` / `dsh-web-shell`）时
  隐藏自己的 rail、面板改浮层、**不再写 `body.marginRight`**，入口只留菜单与 `Ctrl+Shift+B`。
  判据是 `performance.getEntriesByType('resource')` 里的插件 bundle id（`/plugins/<id>/client.js`），
  **不刮 DOM**；插件异步加载所以会再探 10 次（1.5s 间隔），探到即定、不抖动。
- **新增 `npm run review-ui-check`（17 项，`review-ui-check.js`）**：真临时 git 仓库 + 真 preload + 页面桩，
  端到端验证「2 块 → 暂存第 1 块 → 分档变成 已暂存1块/未暂存1块 → 提交 → 剩下那块仍在工作区 → 共存让位」。
  其中两项是跨层校验：**后端确认只有第一块进了暂存区**、**提交信息与 `git log` 一致**。
