## C. 修 Electron 门禁"打印 PASS 后挂死"（提交 `e370686`；崩溃护栏 `abbabb3`；产物 `f33d786` / `77a06c8`）

**症状**：`verify:writing-review-probes` / `verify:writing-baseline-ui` 报 `exit=null`
（600s / 900s 超时），而且都是"所有探针 PASS 之后"才挂，看起来像偶发。

**根因**：多个门禁把**别的门禁当模板重编译**（`m._compile(source, 本文件路径)`）。模板源头
`scripts/verify-writing-chat.cjs`、`verify-writing-ui.cjs` 顶部现在 `require('./lib/electron-gate.cjs')`；
相对 require 按**模块文件**解析，在 recompiler 里 `__dirname` 指向使用者目录
（`docs/audits/.../v2-review/`）→ 去找 `v2-review/lib/electron-gate.cjs`（不存在）
→ Electron 主进程加载即抛、进程不退 → 父进程按超时判失败。

**修法**：9 个 Electron 门禁统一改成
`require(require('node:path').join(process.cwd(), 'scripts/lib/electron-gate.cjs'))`
（所有门禁的 spawnSync 与 npm scripts 都以仓库根为 cwd）。附带：`ui-probes.cjs` 的
`server.close()` 前先 `closeAllConnections()` 并给关闭加 2s 上限，避免同类 keep-alive 挂住。

**验证**：baseline-ui 900s → **9.0s 通过**；review-probes 600s → **3.3s 通过**；
`npm run verify:writing-quick` **QUICK exit=0**。

## 我这一轮犯的错（一并记）

1. **用 PowerShell 多行 `git commit -m "..."` 提交**：换行把那串消息拆成多个 pathspec，
   提交直接失败，而随后的 `git push` 把**对家已有的提交**推了上去（`c22b846`），看起来像"提交成功"。
   教训：多行提交信息写文件 + `git commit -F`。
2. **在 `ui-probes.cjs` / `baseline-ui.cjs` 里先打补丁再定位根因**：两次都在"模板使用者"侧改写，
   而问题在"模板源头"。根因统一后那两处补丁成了死代码，已回退，只保留 `closeAllConnections` 硬化。

## G. 「居然会出现三份通知」（提交 `bba5d00`）

用户截图实证：开写作模式拉起三个窗口（写作伙伴 / 工具台 / 写作台），**每个窗口都弹一份「预览版说明」**。

机制：这是内核 Web 应用在**每个窗口挂载时各自渲染**的一次性通知。三个窗口同源共享 storage，但谁先
点「继续」都不通知别人 ⇒ 首次运行时同时出现 N 份。

内核零修改，改外壳：`web-contents-created` 一处挂钩 → `did-finish-load` 时对**非主窗口**执行
「按文案找『预览版说明』最内层容器 → 点它里面的『继续』」；找不到就什么都不做。主窗口保留一份。
选中只按文案、不依赖内核类名，内核改样式不会失效。

验证：注入脚本先在活着的窗口里手工试过（返回 `clicked`）；`node --check main.js` 通过；`npm run smoke` 正常。

**未完成的实证（不写成"已验证"）**：没能在"真·首次启动"下数出"恰好剩 1 份"——这份通知的"已读过"
