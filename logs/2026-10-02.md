## 写作模式 UX 收口：让失效与状态都说话（接 0.1.7 适配遗留项）

- **做了什么**：上一轮（2026-09-26「写作模式 0.1.7 适配」）末尾写着「kimi 的未竟项只剩 UX 层」。这一轮把这条欠账做实，主题是**能力缺口和保存状态必须在界面上说得出话**，不再让作者对着灰按钮猜。

  1. **能力缺口翻译层**（新文件 `src/client/features/companion/capability-notice.js`，纯函数、不碰 React/DOM）。adapter 一直在算 `missing` / `degraded`，但**没有任何组件读它**——缺口在界面上的全部表现就是输入框和按钮自己变灰。现在按三级出话：`blocked`（连不上内核）/ `limited`（能用但受限）/ `ok`（什么都不渲染，不加噪音）。作者文案里不出现 `sessions.binding`、`remote.session.create` 这类能力名；`noteAgentPreset` 这种对作者没有影响的能力位直接不列。
  2. **伙伴面板**：顶部按级别渲染一条 `dshWmCapability`（`data-wm-capability="blocked|limited"`），说清「缺什么 / 还能做什么 / 想法会不会丢」。**连不上时输入框改为可写**（以前 `disabled: !sessions`，作者连"先记下来"都做不到；草稿本来就另有本地存档，禁用它没有任何收益），placeholder 换成「先记下来，伙伴恢复后再发…」；发送键与「会话设置 ↗」仍禁用，但 title 带同一句原因。「＋ 引用稿件 / 选区」和「本次参考备忘」展开面板改为始终可用（它们只走 host HTTP 与本地缓存，不需要内核会话）。`send()` 捕获到 `capabilities-missing` 时把内核能力名清单换成作者文案。
  3. **写作会话列表**（`SessionListSection.js`）：以前 `!sessions` 直接 `return null`，`api('config')` 失败也被 `.catch(() => {})` 吞掉——整块静默消失等于"这个功能不存在"。现在不可用留一行原因，读取失败留原因 + 重试按钮。
  4. **保存/读取失败常驻可见**（`WritingModeApp.js`）：原来 `notice = documentState.error || flash`，失败文字挂在**浮层**上（`.dshWmFlash` 是 absolute 悬浮条，会挡稿面、没有出路），而状态条在"保存失败且仍有未保存文字"时显示的恰恰是跟正常状态一模一样的「未保存」；更糟的是自动保存 effect 在 `status==='error'` 时**永久跳过**，作者不重打一个字就再也不会重试。现在浮层只承载瞬时提示，稿面下方新增常驻失败行 `dshWmDocAlert`（role=alert）带「重试保存」「另存新版」两条出路，状态条文案改为 `打开中… / 保存中… / 保存失败 / 读取失败 / 未保存 / 已保存`（原来干净稿打开后一直显示一个「—」），顶栏保存键失败时转为「重试保存」。
  5. **专注模式**：`aiTab==='companion' && !focus` 会让伙伴面板在进专注时**卸载**、退出时重挂——重挂的 mount effect 会 `attach` + `openFullSession()`，即作者只是想看会儿稿子，出去时原生主视图被顺手重新聚焦了一次。改为组件常驻、由 CSS 收起。另外专注模式下右栏被 CSS 整体隐藏，此时顶栏「AI」按钮按了没有任何反应（死键），现在点它 = 退出专注 + 唤回右栏。
  6. **快捷键提示自相矛盾**：欢迎页写 `Esc · Ctrl+S · Ctrl+Shift+S`，文字工具 tab 写 `Esc · Ctrl+S · Ctrl+Shift+W`，两处都不带说明、且后者列的不是本面板动作。统一成 `KEY_HINT` 一处定义：「Esc 退出 · Ctrl+S 保存 · Ctrl+Shift+S 另存新版 · Ctrl+Shift+W 开关写作台」。
