  - `main.js`：启动时生成补丁（file:// URL + out 路径到 userData），spawn 内核加 `--patch`，每次启动重置流；`shell:session-changes` IPC 读流
  - `preload.js`：侧边栏加「会话改动 / Git 工作区」双视图切换，会话视图按轮次分组、写/改徽章、old→new 片段

- **现象**：用户点「检查更新」无反应、重启也无提示；kernel.log 显示 `update available: 0.1.3` 之后跟着 `ENOENT ...resources\app-update.yml`
- **根因**：两步构建法（`--dir`+`--prepackaged`）不生成 `app-update.yml`，而 electron-updater 在**下载阶段**硬依赖该文件；之前误判"代码里 setFeedURL 了就够"，实际下载必须它
- **修复**：`build.ps1` / `build-macos.sh` 在打包后显式写入 `resources\app-update.yml`（github provider 配置）；重建并覆盖发布 v0.1.3（Win 本地 + mac CI run 31737046369）
- **影响**：0.1.2 无法自动下载（旧包缺文件），需手动装一次修复版 0.1.3；之后 0.1.4+ 自动更新才真正可用

## ㉑ 长路径修复（升级卸载失败根因）

- **现象**：0.1.3 升级时又报 `Failed to uninstall old application files: 2`，且每次升级都失败
- **根因（实测）**：安装目录最大路径 269 字符（超 Windows 260 上限），共 36 个文件超限——最深的在 `@mistralai/mistralai/.../*.d.ts.map`；NSIS 卸载器用经典 API 删除时报 ERROR_FILE_NOT_FOUND(2)
- **修复**：`prepare-runtime.ps1` / `prepare-runtime-macos.sh` 剪掉 `.d.ts`/`.d.ts.map`/`.map`（开发期产物）；路径 269→228、超限 0 个、体积 339→280MB；剪枝后内核 + 审阅桥启动验证通过
- **发布**：v0.1.4 双平台；用户的 0.1.2 带长路径仍需「删目录+全新安装」一次（`升级到014.cmd`），之后升级/自动更新才走通
- **教训**：自包含打包含 npm 完整树，必须剪枝 + 校验 `max path < 260`

## ㉒ v0.1.5：hoisted 运行时根治长路径

- **背景**：0.1.4 剪枝后安装目录仍有 7 个文件超 260（mistralai esm .js 263、opentelemetry build/esnext|src 变体 261–266）
- **侦察**：mistralai 是死依赖（不在 dsh 依赖、无 @deepseek-ai 包引用）；`dsh-base`/`dsh-web-app`（正式依赖）传递覆盖 dsh-session/dsh-llm/dsh-subagent/dsh-tools/host-webserver/apiproxy → CLI 的 devDeps 冗余，普通 `npm install` 即可装全
- **修复**：`prepare-runtime` 改为 hoisted `npm install`（浅目录）+ 剪枝加 `.ts`；实测 max path 198、超限 0、内核 + 审阅桥启动验证通过；安装包 159.5MB
- **发布**：v0.1.5 双平台；用户 0.1.4 仍带 7 个长文件，需「删目录+全新安装」最后一次（`升级到015.cmd`）
- **坑**：构建中途被中断一次（安装器停在 0.5MB）→ 重跑；node 59692 是用户桌面版内核进程，不可杀（AGENTS.md 生效）
