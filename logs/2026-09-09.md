# 2026-09-09

## 〔103〕 内核 0.1.2-rc.1 撤回（渲染变形实锤）+ 外壳 0.1.33 发布

#### 结论先行：0.1.2-rc.1 内核前端导致 palis 主题球体/月面变形，撤回；外壳修复独立成 0.1.33，内核钉回 0.1.1-rc.1

昨天（〔102〕）把内核升到 0.1.2-rc.1 并做了 token 鉴权适配。今天用户在桌面端
实测发现：palis 主题的粒子球体、右侧月面、声纳波纹全部「不圆」（DPR 2.73
高分辨率下肉眼可见的拉伸变形）。多轮主题侧修复未愈后做 A/B 对拍：

- 同主题 v0.5.7、同外壳，内核 0.1.2-rc.1 → 变形复现；
- 同主题 v0.5.7、同外壳，内核 0.1.1-rc.1 → 用户确认「这个版本是没有变形的」。

→ 变形元凶是 0.1.2 内核前端的合成层路径（静态截图全圆、逐像素量过无变形，
只在实时渲染出现；与 palis WORKLOG §58/§59 记录一致）。处置：内核钉回
0.1.1-rc.1（prepare-runtime.ps1 锁回），外壳的 token 鉴权适配全部保留
（向后兼容，老内核自动退化；未来内核再上 0.1.2 时外壳已就绪）。

#### 事故：换 runtime 三连 EPERM boot failed

已安装实例回退 0.1.1 时，外壳 `ensureExternalRuntime` 连续三次
`内核运行时切换失败：EPERM: operation not permitted, rename .runtime-extract/runtime -> runtime`。
根因：调试用的测试内核进程（17891 端口）从
`%LOCALAPPDATA%\DeepSeek Harness Desktop\runtime\` 起的服务、未退净，
Windows 下目录被占 → rename 必败。手动解 tar.gz 落位后才恢复。

教训（已同步 palis WORKLOG §59）：**换 runtime 前必须杀干净从该目录起的
node 进程**。

#### 改动（main.js）

- `ensureExternalRuntime` EPERM/EBUSY 韧性：rename(extracted→local) 失败时
  先把 `.prev` 备份捞回原位，再查 `complete(local)`——完整则记 WARN 降级
  沿用现有运行时照常启动（marker 不变，下次启动自动重试解包，锁释放自愈）；
  只在本地完全无可用内核时才 throw。直接把今天的事故场景变成无感降级。
- 〔102〕的外壳修复随本版发布：重启路径 `reload()` → `loadURL(kernelPageUrl())`
  （重启后旧端口旧地址已死，reload 只重请求死地址——老内核潜伏 bug）。
