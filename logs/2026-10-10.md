## 写作模式前端第二轮整合（跨夜续 10-09 第一轮）

**背景**：10-09 第一轮（rail 收展 / 左栏缩进 / tab 3→2 / 文字工具抽屉 / 术语白话化）当夜已由 ZCode 的 v0.1.53 发布流程一并入库（`4a35798`，发布前用户裁定「等对方改完再发」）。本轮是用户看过第一轮预览后的追加反馈：顶栏开关多余、抽屉与输入割裂、左栏分组仍挤。改动在**工作树未提交**，等用户发话。

### 改了什么

1. **顶栏删两个面板开关**（`src/client/app/TopBar.js`）：「库 ⟩」「AI」及随之不再用的 props（libOpen/setLibOpen/aiOpen/setAiOpen）删除；顶栏只剩 库选择 / 专注 / 辅助▾ / 保存 / 退出。收展全走边缘 rail + 面板头折钮。
2. **文字工具收进输入框旁 ✦ 图标菜单**（Codex「+」式）：
   - `src/client/features/companion/index.js`：`.dshWmComposeFoot` 最左 `.dshWmToolsBtn`（textContent 逐字 `✦`，title/aria='文字工具'）+ 上弹菜单 `.dshWmToolsMenu`（常挂载 + 关闭 display:none；菜单行可见文本逐字等于工具名，说明放 title）。点工具 = 进入 armed：chip「✦ 润色 ×」（`data-wm-tool-armed` / 取消钮 `data-wm-tool-disarm`）压在输入框上方、输入框聚焦、placeholder 换成 `T.toolsArmedHint`；Enter 或发送键运行（armed 时发送键改作运行键，disabled 只看 tools.busy——assist 走插件自有路由，不依赖内核会话能力）；单次性：运行后 `updateDraft('')` 清空并解除；×/Esc 取消（armed 时 Esc 只取消工具）。产出区（`.dshWmAiOut` + 插入文末/替换选区/发送到会话）从右栏抽屉挪到输入框正上方 `.dshWmToolOut`，落稿回路（applyInsert/applyReplace/sendToChat）不变。
   - `src/client/app/WritingModeApp.js`：抽屉 JSX 与 `toolsOpen` state 删除；新增 tools 束 props 经 WritingCompanion 透传（busy/err/out/onRun/onInsert/onReplace/onSendChat，状态仍在 App）。
   - `src/client/copy.js`：新增 toolsMenu / toolsArmedHint / toolTitlePolish…Spark 七条（zh+en）。
3. **提示词进指令**（`plugin/writing-mode/lib/domain.js` `assist()`）：新增 `hint` 字段——「作者补充要求」拼在动作默认指令之后（不替代默认约束；`instruction` 仍是完整覆盖，老调用方不变）；llm 缺席的「可直接发送到会话」降级文案同样带上补充要求。App 侧 `runAssist(action, hint)` 空串不落字段。
4. **左栏章节优先**（`src/client/features/library/LibraryPane.js`）：作品导航视图且有「正文」分组时，正文文件直列在项目操作行下（不再有「正文」分组行）；其余分组收进 `<details class="dshWmProjAssets">`「资料与设定 · N」（默认关闭、常挂载可点；libQuery 非空或内含当前打开文件时自动展开）。无正文组的项目（独立文稿）与文件/大纲视图维持平铺。`styles/writing-css.js`：`.dshWmProj>.dshWmItem` 与操作行对齐、`.dshWmProjAssets` 子组嵌套缩进。
5. **CSS**：删 `.dshWmTools` 抽屉规则组，新增 `.dshWmToolsAnchor/.dshWmToolsBtn/.dshWmToolsMenu/.dshWmToolsMenuRow/.dshWmToolChip/.dshWmToolChipX/.dshWmToolOut` 规则组。

### 门禁

- `scripts/verify-writing-ui.cjs` 三段改写：✦ 菜单段（开菜单 → arm → 断言 chip → disarm）；专注段改走「专注」钮退出（顶栏 AI 已删、专注中 rail 隐藏——这是**唯一断点**，其余 `button('AI')` 均为新挂载后首次开栏、命中 rail）；改稿回路走 ✦→润色→输入提示词→Enter，fixture 假 llm 记录 prompt，断言 `lastPrompt.includes('语气再轻一点')`（hint 端到端进指令）。

## 写作模式左栏视觉分层（第三轮，纯 CSS）

用户反馈：左栏「视觉比重太统一，没有主次之分」。诊断：`.dshWmFolder` 12.5px 粗体大写比章节行（同 12.5px 常规）更抢眼，层级倒挂；档案/成书/添加资料操作行是描边实钮，与内容同量级；三视图切换是描边药丸，chrome 压过内容。

### 改动（`plugin/writing-mode/src/client/styles/writing-css.js`，markup 零改动）

- **主=章节**：`.dshWmProj>.dshWmItem` 升 14px（--wm-text-md）正文色，列表里唯一大号字。
- **次=项目名**：`.dshWmProjToggle` 升 14px 中黑，靠字重压过章节、不靠边框。
- **再次=分组文件夹**：`.dshWmFolder` 降 11px 中黑灰标签（原 12.5px 粗体 700 + uppercase 退役；`.dshWmFolder.is-clickable` 的 text-transform:none 补丁随之删除）。「资料与设定」容器继承同款。
- **三级=操作行**：`.dshWmProjOps` 按钮去边框、降 xs 灰字，hover 才回正文色；添加资料下拉缩小降权。
- **chrome 让位**：`.dshWmLibViews` 三视图切換改无边小字 tab（选中态淡底+中黑）；搜索框透明底细边（`.dshWmSearchWrap .dshWmSearch` 0,2,0 压住基础 `.dshWmSearch`，焦点态用同优先级补品牌色）；项目间距 12→18px。
