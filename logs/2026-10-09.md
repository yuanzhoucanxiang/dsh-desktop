## 写作模式：工作区（库根）可以像官方一样"选文件夹"

用户反馈：「给工作区加上像 dsh 一样可以自己选择电脑文件夹当工作区的功能，现在只能手打盘符，不够方便」。

### 先查契约（结论：官方桌面版已经给了桥，直接用）

| 事实 | 证据 |
|---|---|
| 官方 Electron 外壳在主窗口页面主世界暴露了 `window.__DSH_DIRECTORY_PICKER__ = { pick() }` | `app.asar/lib/preload-app.cjs`：`electron.contextBridge.exposeInMainWorld("__DSH_DIRECTORY_PICKER__", { pick: () => ipcRenderer.invoke(DESKTOP_IPC.directoryPick) })` |
| 主进程那侧就是官方"添加工作区"用的同一个系统对话框 | `app.asar/lib/main.js` `installDesktopDirectoryPicker`：`dialog.showOpenDialog(window, { properties: ["openDirectory", "createDirectory"] })`；取消回 `null`，否则 `filePaths[0]` |
| 主窗口 URL 是 `dsh-app://app/`，所以那段 `location.protocol === 'dsh-app:' && hostname === 'app'` 门禁成立 | `main.js`：`window.loadURL(\`${this.origin}/\`)`、多处 `mainFrame.url.startsWith("dsh-app://app/")` |
| 官方自己的客户端插件就是这么用的 | `dsh-client-ui-directory-picker-native/lib/client.js`：`const desktop = globalThis.__DSH_DIRECTORY_PICKER__; const pick = desktop === void 0 ? () => ctx.uiWorkspace.pickDirectory() : () => desktop.pick()` |

### 两个环境坑（都会造成假红/假绿）

1. **本机 shell 带 `ELECTRON_RUN_AS_NODE=1`**（DSH 应用给子进程的环境）：所有 `electron .` 会退化成纯 node 跑，`main.js` 在 `require('electron-updater').autoUpdater` 处直接崩，冷启动门禁假红（`Node.js v24.18.1` 而不是 Electron 的崩溃横幅就是线索）。**跑任何 Electron 门禁/打包前先 `Remove-Item env:ELECTRON_RUN_AS_NODE`**。第一次 `verify:writing-quick` 就是这么假红的（5 项里 2 项 FAIL），清掉后 12/12 全绿。
2. **`npm run dist` 的第一步 `plugin-selector-check` 是既有红灯**：内置插件 `dialog-optimize` 依赖的 4 个内核 hash 类名（`Md3f7G_older` / `gdEzaW_bubble` / `p-xYUq_actions` / `p-xYUq_timeStart`）在 0.2.0 内核里已不存在 → 它的**折叠/导航/撤回在 0.2.0 上静默失效**。v0.1.52 应是直接走 `build.ps1`（release 路径）发布的，所以这个红灯此前没拦住发版。本次同样按 release 路径发布，**缺陷另行修**（改走官方 Slots 或更新选择器）。
