- 执行 `plugin/writing-mode/test/hunt-host.mjs`。脚本原先未跑完；补齐后确认并修复两处宿主真实缺陷：
  1. **H3 覆盖写**：`create-project` 只检查 `project.md` 是否存在。目标目录若已有内容但无 `project.md`（例如手写 `bible/`），模板会覆盖原文件。
  2. **H4 目录名逃逸/落库根**：标题清洗后仍可为 `.` / `..` / `...` / Windows 保留名（`CON` 等）。`title='.'` 时 `path.join(root, '.')` 指向**库根本身**，`resolveUnderRoots` 对 `rel===''` 放行，会把模板写进库根。
- 实现（`lib/store.js` + `index.js`）：
  - `safeProjectDirName`：剔除非法字符后拒绝空名、纯点段、Windows 保留名。
  - `prepareProjectTarget`：目录名安全 + 严格位于库根之下（`rel` 不得为空）+ 无 `project.md` + 目录不存在或为空；否则 `invalid-project-name` / `path-outside-roots` / `project-exists` / `directory-not-empty`（后两者 409）。
  - `isSafeTemplateRel` + 写入前二次 `resolveUnderRoots`：模板 `rel` 禁止 `..`/绝对路径/空段。
  - 空目录仍允许脚手架写入（非漏洞）；已有 `project.md` 或非空目录拒绝。
- 客户端 `WritingModeApp.js`：为 `directory-not-empty` / `invalid-project-name` 增加中文提示；`npm run build:writing` + `verify:writing-build` PASS。
- 协议测试 `review5-protocol` / `review7-status`：VM 沙箱加载 `client.js` factory 时缺 `document`（micromark DOM 解码）与 host React `require`。补齐最小 `document` + `react`/`react/jsx-runtime` stub（不改生产 bundle）。

## 〔策划案 v0.7〕世界观：AI 引导与整理（设计定稿 · 未实现）

- **做了什么**：与作者对齐产品方向后，将世界观能力写入策划案；**仅文档，未改 `plugin/writing-mode` 实现**。
- **产品判断**：
  - 不要「照搬模板填空」；主路径是 **AI 引导创作 + 整理讨论结果**。
  - 整理来源 = 用户与 AI 的讨论结论，不是空表单生成。
  - 双读者：**可读**（人阅读回想）且**可用**（AI 助手默认注入/检索）。
- **设定条目字段（定稿）**：标题 / **结论**（一句，可独立成立）/ **说明**（一小段 2–4 句，人为主，**不进默认注入**）/ 边界·例外（可选，有则随结论注入）/ 来源（讨论或消息）/ 状态（候选 → 已确认，语义对齐项目备忘）。

- **本阶段非目标**：关系图/结构化实体库、bible 与正文一致性门禁、强制分步向导。
