## 写作模式第十轮：提问改定时模式 + 文本选项通道（「点一下就继续」）

用户选定「丁 + 丙+，时限 60 秒」。上一轮交付的提问卡只能看见问题、答不了阻塞中的提问（内核契约），这一轮把那条路真正打通。

### 先核准的事实（决定了实现方式）

- `ctx.userQuestions.answer` **只从 `continued` 里找问题**：`dsh-user-questions/lib/index.js:552-554`（`const question = this.continued(agent).find(...)`）。
- `open → continued` 的**唯一**触发：`tool/result` 返回 pending（时限到）或持有它的进程死掉（`lib/index.js:216-228`，另见 `TOOL_OUTCOME_UNKNOWN`）。
- 官方回答器在瀑布里**先注册**（`ui-user-questions` 在 web-app bundle 里，早于 profile patch 插入 writing-mode），且它对能定位到 session 的请求一律自己持有（`ctx.sessions.scopeOf(owner)` 拿得到就 `answerQuestion`）→ 写作助手注册 fallback 也拿不到请求。

结论：**阻塞模式下的提问，客户端永远够不着**；要"点一下模型就继续"，只能走文本通道；工具通道要能用，必须先把提问改成不阻塞的定时模式。

### 踩坑（三条都值得进 WORKLOG 速查）

1. **Windows 文件系统大小写不敏感**：`src/client/Entry.js` 与入口 `entry.js` 是**同一个文件**——
   写 `Entry.js` 直接把入口覆盖了，esbuild 报 `No matching export ... for import "WorkbenchEntry"`；
   删除 `Entry.js` 又把入口删掉。组件改名 `FooterEntry.js`，并在入口注释里钉死"本目录不要再出现只差大小写的文件名"。
2. **`ELECTRON_RUN_AS_NODE=1` 是从 DSH 进程继承来的**：agent 自己活在 Electron 里，直接跑
   `npx electron`（以及任何含 electron 步骤的 npm 脚本）会以 **node 模式**启动，`app` 为 `undefined`
   （`TypeError: Cannot read properties of undefined (reading 'setPath')`）。
   跑 electron 验收前必须 `Remove-Item Env:ELECTRON_RUN_AS_NODE`，或用 `node_modules\electron\dist\electron.exe`。
   **这条对以后所有 electron 门禁都适用**，建议进 `WORKLOG.md` 踩坑速查。
3. **`executeJavaScript` 不能返回函数**：探针里 `registerMode()` 返回的是 disposer，Electron 会报
   `An object could not be cloned`；探针代码要包成可克隆值（`(() => { ...; return 0 })()`）。
