## 〔102〕 内核 0.1.1-rc.1 → 0.1.2-rc.1：外壳 token 鉴权适配（用户「直接安装新内核，并对其进行桌面端的更新适配」）

#### 结论先行：0.1.2 的 Web 一次性 token 鉴权会让旧外壳永远等不到就绪

0.1.2-rc.1 内核起，`dsh web` 对每个进程启动生成一次性 launch token：
启动行 `dsh web: http://127.0.0.1:<port>/?token=<…>` 是唯一入口；
`GET /?token=X` → 303 + 签发签名 cookie（绑定 host:port、默认 30 天），
之后凭 cookie 通行；无 token 无 cookie 的 `/` 恒 401、`/api` 恒 401。
无关闭开关（`BrowserAuth.create` 无条件挂）。

旧外壳三处全中：
- `probeReady` 只认 `res.ok` → 401 = 永不就绪 → 120s 超时 → 补丁降级链
  full→bridge→none 空转三轮后放弃（实测 kernel.log 完整复现）；
- `win.loadURL(state.url)` 裸 URL → 窗口只能停在 401；
- 外壳自己的 `/api/*` 调用（palis-theme 联动、review-bridge/revert）
  无 cookie → 401。

#### 改动（main.js，全部兼容老内核）

1. `captureWebUrl`：解析内核 stdout 的 `dsh web:` 行，带 token 完整 URL 存
   `state.webUrl`（每次 startKernel 重置——token 随进程轮换，端口也换）。
2. `probeReady`：接受 401/303——服务应答即就绪，鉴权是预期行为。
3. `kernelPageUrl()`：`win.loadURL` 一律改用它（webUrl 优先，老内核回退裸
   origin）。内核重启路径的 `webContents.reload()` 改 `loadURL(kernelPageUrl())`
   ——重启后旧端口旧 token 全死，reload 只会重请求死地址（这在老内核就是
   潜伏 bug，0.1.2 把它变成必现）。
4. `kernelApiFetch(path, init)`：外壳侧 /api 统一入口。首次用 webUrl 里的
   token 换 cookie（redirect:manual 摘 set-cookie），缓存进
   `state.webCookie` 随请求带 `cookie` 头；老内核无 set-cookie，退化为
   普通直连，行为与从前一致。

#### runtime 侧（已安装实例 + 构建管线）

- `resources/runtime.tar.gz` 置换为 0.1.2-rc.1 树（360MB→87MB gz，
  GNU tar 打包，`runtime/` 前缀与 bsdtar 解包契约一致），
  `runtime-marker.json` 同步（dsh/node/builtAt 三字段相等才跳过重解包）。
  原版备份：resources/runtime.tar.gz.bak-0.1.1 / runtime-marker.json.bak-0.1.1 /
  app.asar.bak-0.1.31。
- 教训：外壳启动时按 marker 对账，不符就重解包——**直接手换
  %LOCALAPPDATA%/…/runtime 会被下次启动覆盖**（本次先踩了一遍，被换血的
  树备份在 runtime.prev，回收进 rollback-0.1.1-manual/）。正路就是换
  resources 里的 tar.gz+marker 让外壳自己解。
- `prepare-runtime.ps1` 锁定版本 0.1.1-rc.1 → 0.1.2-rc.1（下次 dist 构建
  自动带新内核）。
- 外壳修复经 `@electron/asar` 重打包进已安装实例（main.js 单文件替换，
  其余字节不动）；仓库源码已同步，下次 dist 自然带全。

#### 主题插件适配（palis-theme-panel 0.5.4）

- 0.1.2 删了 `dsh-settings` 的 `settingsNamespace()` 帮助函数——命名空间
  直接传小写连字符字符串。插件仅此处断 API，`src/index.ts` 两行修完。
- 0.1.2 的「会话视图拆分/会话流默认折叠」未冲垮主题 DOM 契约：
  预览内核全套回归 7/7 绿（glyphs/craters/flat/flicker-mech/moon-teleport/
  panel-switch/ping-invisible），截图目检正常。

#### 验证

- 桌面端重启：kernel.log `ready at` 一次到位，无 boot failed 降级循环，
  无 401 报错，palis-theme push 静默成功（cookie 链路通）。
- 就绪探测实测：旧外壳对 0.1.2 内核 probe 恒 401（复现重启循环），
  新外壳同条件 probe 通过。
