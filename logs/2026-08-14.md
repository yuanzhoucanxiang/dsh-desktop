## ① 内置 dialog-optimize 插件（对话框人性化优化）进桌面版

- **做了什么**：
  - 用户提供 `E:\dsh 插件\dialog-optimize`（对话框折叠 / 对话导航 / 消息撤回+文件回退 三合一插件），要求适配为桌面版**内置插件**。
  - 摸清 dsh 客户端插件加载机制：`dsh-client-modules`（Node 半）按 loader 条目名 `require.resolve('${name}/package.json')` 读 `dsh.client.platform=web` 声明 → 把 `exports['./client']` 作为 bundle 注入 `window.__DSH_BOOT__` 图形 → 浏览器经 `__ModuleLoader__.load()` 注册 factory。**结论：`file://` URL 命名的行带不了 client 半，必须用可解析的裸包名**。
  - 解析锚点：`boot()` 不传 `bareModuleBaseUrl`，裸包名从 profile 目录（`$DSH_HOME/profiles/web/`）向上走 node_modules；`healProfilesModuleFallback` 已在 `$DSH_HOME/profiles/node_modules/` 给 `@deepseek-ai/*` 建好链接 → **内置方案 = 外壳把插件同步到 `$DSH_HOME/profiles/node_modules/@dsh-local/dialog-optimize/`，补丁行用 `name: '@dsh-local/dialog-optimize'`**。
  - `dsh.client.inject` 里的 `'sessions'` 不是模块 id（种子词表里没有）——但它是**客户端服务名**（app-shell 自己也 inject `sessions`），且图形 inject 边在 `dsh-client-web` 的 `runPluginBoot` 里并不参与 `loader.create`（只传 name），真正生效的是 client.js 里 `exports.inject=['sessions']`。插件文件零改动。
- **改动文件**：
  - `plugin/dialog-optimize/{package.json,index.js,client.js}`（从 `E:\dsh 插件\dialog-optimize` 原样拷入，随包分发）
  - `main.js`：`state.useReviewBridge` → `state.patchMode`（full/bridge/none 三级）；新增 `dshHome()`、`syncBuiltinDialogPlugin()`（hash 比对后同步到 profiles/node_modules）、`userInstalledDialogOptimize()`（检测用户补丁层已有同名行则跳过内置行，防重复 loader 条目）；`writeReviewPatch()` → `writeKernelPatch(mode)`，双行输出，补丁文件改名 `kernel.patch.yml`；`bootKernel()` 失败降级改为**三级**：full → bridge → none

- **结果**：

## ② 打包坑：extraResources filter 子目录不生效 + winCodeSign 下载卡死

- **做了什么**：0.1.6 首次构建后发现 `resources/plugin/dialog-optimize` 没进包——extraResources 的 filter 用 `"dialog-optimize/package.json"` 这类带子目录的模式在 Windows 上不匹配（filter 的匹配路径经 `path.join(relativeFrom, pattern)` 拼出反斜杠，minimatch 模式里反斜杠被当转义符，只在 basename 匹配时无此问题，所以 review-bridge 的顶层文件名模式一直正常）。**修复**：为 dialog-optimize 单独建一条 `from: plugin/dialog-optimize` 的 extraResources 条目，filter 用纯 basename（`package.json`/`index.js`/`client.js`），实测进包成功。
- **做了什么（续）**：构建期间 GitHub 下载 winCodeSign-2.6.0 反复 TLS 断连/超时（10 分钟 request 超时），electron-builder 的归档缓存路径是 `%LOCALAPPDATA%\electron-builder\Cache\winCodeSign-2.6.0\winCodeSign-2.6.0.7z`——从 npmmirror（`registry.npmmirror.com/-/binary/electron-builder-binaries/winCodeSign-2.6.0/winCodeSign-2.6.0.7z`）手动下载，sha256 校验与官方一致（`cdaec715...`）后放入缓存，构建即跳过下载。7zip/nsis 同理（已有缓存）。electron 本体走 `%LOCALAPPDATA%\electron\Cache`。
- **结果**：`npm run dist` 全量构建成功，`dsh-desktop-0.1.6-setup.exe`（167.3MB）；win-unpacked 含 dialog-optimize 三文件 + app-update.yml；打包版冒烟（独立 userData）SMOKE_OK；打包运行时内核验证 BOOT_GRAPH / client.js / recall 端点全部通过。
- **坑 / 备注**：打包版测试必须用 `Start-Process -RedirectStandardOutput` 捕获 stdout（`& '.\dist\...exe'` 会被 PowerShell 当成 cmdlet 名解析失败）。
