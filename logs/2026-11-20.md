## 一、Electron 门禁的环境假红（真 bug）

**症状**：直接跑
`electron.exe scripts/verify-workbench-writing-integration.cjs` 得到

```
TypeError: Cannot read properties of undefined (reading 'setPath')
    at Object.<anonymous> (...verify-workbench-writing-integration.cjs:23:5)
```

**原因**：环境里带着 `ELECTRON_RUN_AS_NODE=1`（本会话的运行器就设了它）⇒ electron.exe 退化成纯
Node ⇒ `require('electron')` 返回**可执行文件路径字符串** ⇒ `const { app } = …` 得到 `undefined`。
报错里**一个字都没提环境变量**，看起来像门禁回归 —— 我为此白查了一轮（先用 `git stash` 对照
才排掉代码因素）。

**修法**：新增 `scripts/lib/electron-gate.cjs`，提供 `assertElectronGate()`：正常环境静态返回；
环境不对就打印可执行修法并 `exit 78`（EX_CONFIG，与业务断言失败区分），9 条 Electron 门禁
（workbench-ui / workbench-writing / workbench-gir / previz-ui / writing-ui / writing-chat /
writing-native / writing-compile / writing-archive）文件头各加一行。

**验证**：

| 场景 | 结果 |
|---|---|
| 带 `ELECTRON_RUN_AS_NODE=1` | 打印「检测到 … 修法：Remove-Item Env:ELECTRON_RUN_AS_NODE」+ **exit 78** ✓ |
| 正常环境 | `WORKBENCH_WRITING_OK`（W1/W2/W3/W5 + L1/L1.5/L2）**exit 0** ✓ |

## 二、`verify:plugins` 把"没准备输入"报成 FAIL（真 bug）

`PLUGIN_COMPAT_FAIL env / 插件树不存在` —— 其实只是没有先跑
`node scripts/prepare-builtin-plugins.mjs` 造 stage 树。红得像是"插件与内核不兼容"。

修：新增 `precheck()` —— 前置未准备时输出 `[SKIP] env …` + `PLUGIN_COMPAT_SKIP` 并 **exit 0**，
同时说清怎么准备；要强校验（CI）加 `--require`，那时仍按 FAIL 处理。
实测两档都对：默认 exit 0 / `--require` exit 1。
