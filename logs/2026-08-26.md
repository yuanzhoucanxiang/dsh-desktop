## 〔88〕 修「模组注入」页崩溃 + super-injector host 回环门禁（本地热修复）

- **背景**：第一轮排查定性的「模组注入页崩溃空白」（React #130）一直没修——
  终于是修的时候了（用户「继续」）。
- **根因**：super-injector v0.3.3 客户端把组件写成
  `options.component: () => ({ render(){…} })` 且 register 只传一个参数——内核
  slots 契约要求组件作第二参数（渲染器取 entry.component），options.component
  无处消费 → undefined → React #130 → 设置区整段崩溃空白。上层源码 v0.3.1
  同款（快照只读不能改）。
- **修法（修正版，非补丁）**：装机副本 ~/.dsh/plugins/dsh-super-injector 的
  client.js 手术——组件改为 React 函数组件（useRef + useEffect 命令式建 DOM，
  原 el()/轮询/拖放逻辑逐行保留），register 改双参数。同步补 host API 回环
  门禁（对端地址，与 palis v0.2.1 同修法）：/inject /ingest 可让内核加载任意
  目录为插件，若内核被 --host 0.0.0.0 绑到局域网时这是唯一防线。
- **验证**：隔离实例实测页面渲染（标题/内化/注入/卸载按钮/列表统计全出，
  /list 正常响应——回环闸未误伤本地页面）；node --check 双文件过。
- **范围说明**：这是对第三方插件安装副本的本地热修复（上游未接受前没有可提
  交的仓库）；工作区快照 dsh-super-injector-main 保持只读未动。真实桌面已重启
  加载修复。修复内容若未来被上游版本覆盖，需重新确认。

— 署名：ox-alpha（ZCode）
