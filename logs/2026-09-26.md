### 升级路径上的硬阻断：既存 profile × 新内核（已修）

日常实例首启在真实 home 上即崩：`2 required plugins did not activate` + 12 条
"parameter codec is not backed by a zod v4 schema"。根因：profile 两级 node_modules 里的
`@deepseek-ai/*` 链接指向**旧运行时**（LOCALAPPDATA / Roaming 全局），新内核顺着链接
解析到旧代码。这正是契约探针 `shell.profile-kernel-packages` 预警的形态——9-25 我按
手册把它当「非升级风险」跳过，**那个判断错了**：手册说的是"探针比对口径会误报"，
而风险本身是真的。

**修法**：`lib/profile-kernel-links.js`（新模块，12 项单测）+ `main.js startKernel()`
接入——每次拉内核前把 profile 内核包条目对齐到本轮运行时（幂等）：
- 链接 → 同族运行时：保留；异族/悬空且本轮内核有此包：重指；内核已无此包：摘除；
- 真目录 → 同族保留；真遮蔽（本轮内核有同名包且异族）或坏目录（package.json 不可读）：
  改名 `.stale-` 让位；本轮内核没有的完整真目录副本保留；
- 只碰 `@deepseek-ai` 作用域，插件链接（如 palis → checkout）一律不动。

### 自伤事故（已完全修复，如实记录）

删了**（同一份代码两种行为；疑与 Electron 内置 Node 的 fs 实现差异有关，未深究机制）。

  **基线 2564 个文件逐一对账，缺失 0**。正在运行的旧内核全程未受影响（in-memory）。
- **全局 npm 的 dsh**（Roaming）：目录被清空 → 从 npm 缓存确认原版本即 0.1.7-rc.2，
  `npm i -g @deepseek-ai/dsh@0.1.7-rc.2` 重装（517 包，bin.js 在位）。有个从该目录起的
  `dsh web --port 8007` 进程在删除前已在跑，靠内存存活，未动它。
- **palis checkout 的两个 junction**（@deepseek-ai/schemastery、dsh-settings → 旧运行时）：
  目标被掏空导致 palis 在真实 home 上 failed to import → 重指到工作区运行时，模块导入 OK。

**修复**：`removeLink` 改 `fs.unlinkSync`（只摘链接本身、语义上不可能碰目标），EPERM/EACCES

## 看板娘桌面图标：修复重申脚本「永远 CHANGED=0」（用户报告桌面图标没变）

用户问「这个图标你没弄进安装包吗」→ 查实：**图标资产一直在包里**（maiden.png 在 0.1.43 起的
asar 文件索引里，0.1.45 同样在），用户 userData 的 maiden.ico 也在——真正坏掉的是**快捷方式
改写脚本本身**：已装应用的日志显示两次重申都是「已更新 0 个」，桌面 .lnk 的 IconLocation
一直指向 exe（鲸鱼）。

- **根因**：生成的 PowerShell 里 `$dirs=@( [Environment]::GetFolderPath('Desktop'), (Join-Path
  [Environment]::GetFolderPath('StartMenu') 'Programs'), …)` —— 出现在命令参数位置上的裸
  `[Type]::Method()` **不被求值**（PS 按字面字符串收下），Join-Path 报错被
  `$ErrorActionPreference='SilentlyContinue'`+`catch{}` 双层吞掉，连带 `@()` 数组求值成**空**
  → 循环零目录 → **自 0.1.43 功能上线起，快捷方式改写从未真正生效过**（"0 个"被当成了正常）。
- **复现/定位过程**：先证明资产在包内（asar 索引）；再对照已装 0.1.44 抓到 CHANGED=0 的日志；
  手写同逻辑 PowerShell 能匹配（Trim-ieq=True）→ 差异锁定在生成脚本本身；把 SilentlyContinue
  换成显式输出后 `dir=[]` 一锤定音。（我自己在复现时还被 shell 转义连坑两次：bash 双引号吃
  反斜杠、数组 map 写错——教训是路径类测试一律写进 .cjs 文件用 String.raw，别走命令行内联。）
- **修法**：每处 `[Environment]::` 调用加括号；测试把旧断言（它钉住的恰恰是坏形态！）换成
  钉括号形态 + 反向断言 `!includes('Join-Path [Environment]')`。7/7 通过。
- **用户侧已当场生效**：用修好的脚本实跑 → `CHANGED=3`，桌面/开始菜单的 DeepSeek Harness.lnk
  IconLocation 已指向 maiden.ico。若桌面图标视觉上还没刷新，是 Windows 图标缓存，F5 或重登即好。
- 修复已提交（65fc202），随 0.1.46 发布（与写作伙伴 adapter 适配同车）；0.1.43–0.1.45 的
  用户升到 0.1.46 后，启动重申才真正开始工作。

## 写作模式 0.1.7 适配：preset 自举注册 + 双栈建会话 + 右栏三区 + 会话列表（kimi 接力）

接 0.1.45 遗留：内核升到 0.1.7-rc.2 后写作伙伴多条 Electron 门禁红（verify:writing-native / verify:writing-existing-ui）。本轮全部修绿，并顺手把「文字工作区」右栏做了整合解耦。

### 改了什么

- **A preset 自举注册**：新增 `plugin/writing-mode/lib/companion-preset.js`（生成物，由 `dsh-desktop/scripts/sync-companion-preset.mjs` 从 `lib/companion.cordis.yml` 生成，`!!js` 平台开关求值为布尔）；`test/companion-preset.mjs` 逐字节漂移门禁（改 yml 必须重跑生成器）。`index.js` 的 `apply(ctx)` 里 `ensurePresetRegistered()` 向 `agentPresets` registry 注册（Duplicate 视为幂等成功，失败重置 promise 允许重试），POST companion `{prepare:true}` 路由装好文件后 await 注册。preset 内容对齐内核 standard（workflow-worker-thread → workflow-ptc 等；0.1.7 根本没有旧包），保留写作人格与 `fetch:false` 差异。
- **B adapter 双栈**（`src/client/adapters/harness/{runtime,adapter}.js`）：`ctxRef` + `tryService(name)` 惰性解析 0.1.7 服务（entry.js 的 inject **不能**加 remote.*/uiWorkspace——0.1.1 没有，加了 fiber 永不激活）。`capabilities()` 重写：modern = `remote.session.create` + `workspaces.create` 齐备，legacy = 旧三步；两端都缺时 missing 并列双栈缺口。
- **建会话必须走 workspaceId**（本轮最重要的实测发现）：host 的 `session.create` 拒绝同时传 cwd+workspaceId；**用 cwd 建的会话不挂任何工作区**，主视图 hero 的 `chipTitle` 解析不到（`sessionWorkspace` 为空且 workspaces 列表已 ready），输入框停在 inert（「选择工作区」），Lexical composer 根本不渲染。修法：`workspaces.create({path})`（host 端按 realpath 幂等复用）拿 workspaceId，再 `remote.session.create({workspaceId, agentPreset})`——host 自动把 cwd 定到工作区路径并 `attachSession`。
- **聚焦**：`focusSession` 优先 `uiWorkspace.openSession(id)`（公开方法 = `replaceMain(id, lifetime.signal, 'reveal')`：释放旧 mainReference + `layout.selectPanel(null)`）。两个坑：① publishMain 有粘性规则（旧会话 mainView>0 就不换人），绕过 uiWorkspace 直接 `sessions.retain(id,{source:'mainView'})` 切不动视图；② 直接调 replaceMain 时**必须传 'reveal'**——之前传的 'preserve' 不会清全局面板，主视图停在 hero。retain/open 兜底保留（无 uiWorkspace 时尽力而为）。
