### 升级路径上的硬阻断：既存 profile × 新内核（已修）

日常实例首启在真实 home 上即崩：`2 required plugins did not activate` + 12 条
"parameter codec is not backed by a zod v4 schema"。根因：profile 两级 node_modules 里的
`@deepseek-ai/*` 链接指向**旧运行时**（LOCALAPPDATA / Roaming 全局），新内核顺着链接
解析到旧代码。这正是契约探针 `shell.profile-kernel-packages` 预警的形态——9-25 我按
手册把它当「非升级风险」跳过，**那个判断错了**：手册说的是"探针比对口径会误报"，
而风险本身是真的。

**修法**：`lib/profile-kernel-links.js`（新模块，12 项单测）+ `main.js startKernel()`
接入——每次拉内核前把 profile 内核包条目对齐到本轮运行时（幂等）：
- 链接 → 同族运行时：保留；异族/悬空且本轮内核有此包：重指；内核已无此包：摘除；
- 真目录 → 同族保留；真遮蔽（本轮内核有同名包且异族）或坏目录（package.json 不可读）：
  改名 `.stale-` 让位；本轮内核没有的完整真目录副本保留；
- 只碰 `@deepseek-ai` 作用域，插件链接（如 palis → checkout）一律不动。

### 自伤事故（已完全修复，如实记录）

第一版迁移用 `fs.rmSync(link, { recursive: true, force: true })` 摘链接。在**系统 node v26**
的单测里它只摘链接（12 项测试全绿），但**在 Electron 43 的 Node 上顺着 junction 把目标内容
删了**（同一份代码两种行为；疑与 Electron 内置 Node 的 fs 实现差异有关，未深究机制）。

损害面（全部查清并修复）：
- **已安装应用的运行时**（`%LOCALAPPDATA%\DeepSeek Harness Desktop\runtime`）：被删的
  @deepseek-ai 包内容 → 用安装包自带的 `resources/runtime.tar.gz`（0.1.1 基线）重放还原，
  **基线 2564 个文件逐一对账，缺失 0**。正在运行的旧内核全程未受影响（in-memory）。
- **全局 npm 的 dsh**（Roaming）：目录被清空 → 从 npm 缓存确认原版本即 0.1.7-rc.2，
  `npm i -g @deepseek-ai/dsh@0.1.7-rc.2` 重装（517 包，bin.js 在位）。有个从该目录起的
  `dsh web --port 8007` 进程在删除前已在跑，靠内存存活，未动它。
- **palis checkout 的两个 junction**（@deepseek-ai/schemastery、dsh-settings → 旧运行时）：
  目标被掏空导致 palis 在真实 home 上 failed to import → 重指到工作区运行时，模块导入 OK。

**修复**：`removeLink` 改 `fs.unlinkSync`（只摘链接本身、语义上不可能碰目标），EPERM/EACCES
时兜底非递归 `rmSync`；单测加「目标内容必须分毫不动」哨兵 ×2。修好后的迁移在真实 profile
上干净跑完：repointed=15 / removed=12 / **零报错**。
