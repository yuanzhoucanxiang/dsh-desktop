# 2026-09-25 · dsh-desktop

## 修复 Windows 发布包丢失应用图标（v0.1.42 资产已替换）

### 现象与根因

用户报告安装后的应用图标变成 Electron 默认图标。根因：自 v0.1.39 起，本地发布为绕开
electron-builder 在 packaging 阶段连 GitHub 下载 electron 的问题，构建配置里带了
`win: { signAndEditExecutable: false }`。这个开关跳过的不只是签名，还有**往 exe 写入图标与
版本信息的资源编辑步骤**——于是 0.1.39/0.1.40/0.1.41/0.1.42 的 Windows 包全部带着默认图标
（macOS dmg 由 GitHub Actions 用正常配置构建，不受影响；NSIS 安装器自身的图标由 makensis
编译时嵌入，也不受影响）。

### 修法

1. **重建 v0.1.42**（用户当前所在版本）：`git worktree add` 到 `v0.1.42` tag（ac00c15，
   不混入工作区里未发布的 hotkey 改动）→ node_modules 以 junction 复用主仓库 →
   `System32\tar` 打 runtime.tar.gz（runtime 自 8 月锁定未变，与 tag 内容一致）→
   `prepare-builtin-plugins.mjs` 产出内置插件树（pnpm 走本地 store；palis v0.5.13 起初
   下载失败、TEMP 缓存已被清理，重试后成功）→ 用 `win: { signExecutable: false }`
   **只跳过签名、保留图标/版本信息**重建 dir 包。
2. **验证**：提取新 exe 的关联图标为 PNG 与默认 electron.exe 对比（哈希不同），人工确认是
   鲸鱼 logo；`verify-writing-package --package` 在 worktree 内 8/8（含 app.asar 主进程模块
   与 tag 源码**逐字节一致**）；真包 `--smoke` → `SMOKE_OK`。NSIS + `gen-update-manifest.js`
   出 `latest.yml` 后覆盖上传 `setup.exe / .blockmap / latest.yml` 三个资产，远端 latest.yml
   的 sha512 与本机构建完全一致（`pA5yN3sA…`）。
3. **防复发**：`scripts/rebuild-package-tmp.mjs` 改为 `signExecutable: false` 并加注释说明
   两个开关的区别；本次提交不包含用户工作区里未提交的 `lib/hotkey.test.js` 改动。

### 用户侧操作

同版本不会触发自动更新（updater 比较 version 相等即跳过）：**到
<https://github.com/yuanzhoucanxiang/dsh-desktop/releases/tag/v0.1.42> 重新下载
`dsh-desktop-0.1.42-setup.exe` 再装一遍即可**（覆盖安装保留 userData/账号/会话）。
装过的旧版本（0.1.39–0.1.41）用户会经自动更新升到修复后的 0.1.42，无需单独处理。

### 坑

- Git Bash 下 `System32\tar.exe -C <带空格路径> runtime` 会把路径咬碎（`es\compiler\lib\mic`），
  必须经 PowerShell 调用（build.ps1 一直是对的）。
- 摘除 worktree 里的 node_modules junction 必须用"删链接本身"的方式
  （PowerShell `(Get-Item …).Delete()` 或 `rmdir`），`git worktree remove` 会递归删除目录、
  跟随 junction 把主仓库的 node_modules 内容一起删掉——先摘链接再 remove worktree。
