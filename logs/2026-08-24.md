## 〔70〕 插件管理面板：按钮式禁用/启用（写 profile cordis.patch.yml，内核热重载）

- **背景**：上午的专项排查（工作区 `日志/2026-08-24.md`）证实内核 web UI 对插件只有
  只读清单（无任何启停 RPC），唯一带操作按钮的管理页「模组注入」又因注册签名不兼容
  崩溃空白——用户在桌面上没有任何按钮式的插件停用手段。用户拍板走「桌面外壳自建插件
  管理面板」路线（内核零修改）。
- **原理**：profile 用户补丁层 `~/.dsh/profiles/web/cordis.patch.yml` 被内核 boot 的
  `watchUserPatches` watch（dsh-app-boot，HMR 服务启动时自动补建），改动事务性重放
  补丁层、免重启生效。禁用 = 写入 `- id: <entryId>` + `disabled: true`；entryId 从各
  插件自己 `dsh.bundle.patch` 的 insert 块解析（非包名机械推导：palis-theme-panel /
  dsh-super-injector / better-sidebar / auto-permission-mode / pet）。补丁只写 id+
  disabled、不带 name——带 name 会触发内核 name 一致性校验，不匹配整条跳过。
- **改动文件**：
  - 新增 `lib/plugin-manager.js`：零依赖 patch 清单 YAML 子集解析器（结构看不懂就报错，
    绝不猜；`!!js` 表达式条目标记 unsupported 拒切）、insert 块 entryId 提取、生效禁用态
    （后写胜出）、行级手术读写（其余行逐字节保留；写前 backupFile + writeFileAtomic 原子替换）
  - 新增 `lib/plugin-manager.test.js`：19 项单测全过
  - `main.js`：`buildManageList` / `togglePluginDisabled` + IPC `shell:plugins-manage-list`
    / `shell:plugins-manage-toggle`
  - `preload.js` / `renderer/settings.html` / `settings.js` / `settings.css`：插件表「启用」列
    升级为开关控件（不可管理的行显示原因：被隔离/不在加载列表/缺 id/文件含手工内容），
    管理横幅提示热重载结果
- **关键实测发现（重要教训）**：**内核热重载对「补丁被移除、列表回到 []」不会回退已生效
  的 override**——第一版启用逻辑删管理块还原空表，E2E 显示禁用能热上、删块不能热撤；
  显式写 `disabled: false` 则秒级生效。已改为**启用 = 把 true 原地翻 false，永不删块**
  （对每个曾经切换过的插件留一条 no-op 块，往返幂等、单块复用）。
- **验证**：隔离实例（DSH_DESKTOP_USER_DATA=%TEMP%\dsh-preview）+ CDP 双通道 E2E：
  设置面板点开关 → patch 文件翻转 → 独立无头 Chrome 新开页面查内核 pluginInventory，
  dsh-pet 关=已停用、开=已挂载，全程未重启内核；19 项单测 + 全部既有单测回归通过。
- **坑**：
  - Electron 主窗口 `visibilityState=hidden`（遮挡/后台）时 rAF 渲染停摆、定时器节流，
    CDP 点击后 UI 迟迟不渲染，探针大量假阴性——GUI 探针要用独立新页面或先 bringToFront；
  - 内核清单页快照在组件挂载时取一次，验状态前必须整页 reload；
  - 已打开会话页的 client 半边在热重载后仍是旧实例（pet 日照常打），需刷新页面才反映
    ——面板横幅已加「刷新该页即可」提示。
- **边界与保护**：内核核心 bundle 与外壳自带组件（review-bridge/dialog-optimize/
  shell-settings 走 kernel.patch.yml 注入）不在管理列表；patch 文件含手工内容解析失败时
  开关整体停用并横幅说明，绝不破坏手工编辑；被隔离/未启用/缺 bundle.patch id 的插件
  不给开关只给原因。
- 未提交 git（等用户发话）；打包分支未涉及。
