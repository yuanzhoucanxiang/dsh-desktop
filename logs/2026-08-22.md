# 2026-08-22

## ㉑ 架构加固 v0.1.21：把「更新出 bug」从灾难降级为可恢复

- **背景**：用户要求彻底优化架构，减少以后版本更新与内容更新出 bug。对着本 session 实战踩过的五类 bug 逐一加防护。
- **改动**（提交 49761bf，已发布 v0.1.21）：
  1. **坏插件自动隔离**：内核对 profile bundle 任一失败即整体退出（PALIS 缺 dsh.bundle、
     工作区插件解析失败都搞挂过整个应用）。`startKernelUntilReady()` 恢复链：失败时
     `detectBrokenBundles()` 从日志提取报错点名的包名（failed to import/apply loader entry
     (pkg)、profile bundle "pkg" declares；cordis:* 与核心 bundle 排除）→
     `quarantineBundles()` 从 profile 的 dsh.profile.bundles 摘除（写 userData 的
     disabled-bundles.json）→ 重试（≤4 轮）+ 系统通知；托盘「重新启用被隔离的插件」一键恢复。
     启动失败仍保留补丁降级链；「重启内核」只隔离不降补丁（慢启动不该丢审阅桥）。
  2. **运行时安全交换**：解压校验完整性（node.exe+dsh 入口+runtime.json）不完整不碰现有；
     切换走 .prev 备份→就位→失败回滚；runtimeRoot() 在主运行时损坏时回退 .prev。
  3. **日志编码**：decodeChunk()——含 U+FFFD 即非合法 UTF-8，用 GBK TextDecoder 解码内核输出。
  4. **更新器残留清理**：killStaleUpdaterInstallers() 在启动与装更新前清 dsh-desktop-updater
     目录里卡住的安装器进程（实战僵尸挡过更新）。
  5. **检查更新重试**（0s/3s/8s）；**读 profile manifest 剥 BOM**（PS5.1 `Set-Content -Encoding UTF8`
     写 BOM，内核 JSON.parse 直接崩——本次测试脚本自己踩中，顺手加了应用侧防御）。
- **实测**（在 %TEMP% 构建，工作区内 dist/dist-alt 均被 ZCode 文件监视锁住 app.asar）：
  - T1 隔离：注入缺 dsh.bundle 的假插件 → 内核崩 → 日志 `quarantined broken bundle: dsh-broken-test`
    → 自动重试 → **SMOKE_OK**；profile 里坏插件被摘、其余（dsh-pet/palis 等）完好。
  - T2 交换：删 runtime.json 制造标记不一致 → 重解压 → `.prev` 备份生成（含 node.exe）→ 原子切换 → SMOKE_OK。
  - 发布后 `--updated` 覆盖安装 0.1.20→0.1.21 退出码 0，内核就绪。
- **坑**：① PS5.1 here-string 单行写法非法；② `Set-Content -Encoding UTF8` 带 BOM 坑了内核；
  ③ ZCode 会锁工作区内新出现的构建产物 app.asar——构建输出必须放工作区外（本次用 %TEMP%）。

## ㉓ 修复：内核"提前退出"——pnpm 跨盘 link 悬空 + 隔离机制盲区

- **现象**：㉒ 补回 bundles 后用户重启应用，内核反复 `提前退出（code=1）`。
- **根因（两层）**：
  1. profile `node_modules` 里 `dsh-better-sidebar`/`@nanmicoder/dsh-auto-mode` 的
     symlink 悬空——pnpm-lock.yaml 把跨盘 link 存成相对路径
     `link:../../../Deepseek harness/...`（从 `~/.dsh/profiles/web` 解析落到
     `C:\Users\DL\Deepseek harness\`，该目录不存在；插件实际在 E 盘）。昨晚
     `dsh plugin add dsh-pet` 触发 pnpm 重链整个 node_modules，两个链接被打坏。
     dsh-app-boot 抛 `cannot resolve profile bundle "dsh-better-sidebar"` 退出。
  2. detectBrokenBundles 只认 `failed to (import|apply) loader entry` 与
     `profile bundle "x" declares`，不认 `cannot resolve profile bundle`，
     隔离机制没兜住 → 用户直接看到启动失败。
- **修复**：
  - 悬空 symlink 删除，改为 junction 指向 E 盘真实包目录（`cmd mklink` 经 Git Bash
    转义会报"卷标语法不正确"，用 PowerShell `New-Item -ItemType Junction` 成）；
  - lockfile 两条 `version:` 改回绝对 E 盘路径（**注意：下次任何 `dsh plugin add`
    后要复查这两个链接是否又被 pnpm 相对化打坏**）；
  - settings.json workspace 复位为默认（应用未运行时直改才有效；此前 `.git` 是
    ㉑ 测试遗留）；
  - main.js detectBrokenBundles 增加 `cannot resolve profile bundle "x"` 匹配
    （node --check 通过，对真实 kernel.log 命中）——此类失败以后走隔离摘除自动重试。
- **验证**：复刻应用启动命令 headless 拉起内核（--no-open）→ 无 bundle 报错、
    HTTP 200 → 测试进程已清理。palis 不在 lockfile 里（手动 junction 装的），
    未受 pnpm 影响。

— 署名：deepseek-v4-flash
