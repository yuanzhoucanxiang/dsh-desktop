## 2. 定位与非目标（写下来，免得越做越像别的产品）

**一句话**：工具台是 dsh 的**门面层**——把若干创作模式收进"一个入口、一个当前模式、一套上下文与交接、
一块辅助坞、一块主屏"；它**不实现任何创作能力**。

非目标（明确不做）：

- 不做统一数据模型（不把写作的作品库与 GIR 的项目记录合并）。
- 不做模式的运行时共享模块（内核 bundle 纯净门禁禁止跨插件值导入；共享是**构建期**的，见 `packages/mode-kit`）。
- 不做壳的事（开窗/热键/通知/退出守卫是**壳能力**，见 plan §6.4；工具台按需申请并能力探测）。
  **例外已获准（2026-10-12）**：把主窗收成"微信长条"这类**窗口形态**也归壳（`main.js`/`preload.js`），
  项目所有者同意为它改外壳（plan §6.4.1 列了逐条代价）。破例的边界照旧：**只加能力、不搬门面**——
  工具台不往 `preload.js` 塞常驻 UI，形态通道只收档位枚举、不收页面传来的任意几何参数。
- 不做真分屏、跨窗口实时同步（现状：只有"主视图 + 辅助坞"，同步靠聚焦刷新）。
- 不在工具台里"假装"任何模式的状态：模式报什么就显示什么，报不出来就显示为空。

## 3. 从 GIR 六份文件借来的条款（以及**不能照搬**的部分）

GIR 项目（`E:\GIR`）与工具台是同一批人、同一套工程文化下的两条线。下面这些条款**已验证有效**，直接沿用；
最后一组是**明确不适用**的，照搬会做错。

### 3.1 直接沿用

| 来源 | 条款 | 在工具台怎么落地 |
|---|---|---|
| 《UI/UX 协作统一规范》§1 | 插件可以有自己的功能与信息结构，但**沿用宿主的外壳、颜色、组件与动效**；不要为了"统一"把插件改造成主产品页面 | 工具台所有样式**只用 `--dsw-*` 设计令牌**（皮肤会重定义），类名统一 `dshWb*` 前缀，不自带第二套品牌色 |
| 同上 §6 | 状态 = **点 + 标签 + 具体原因**，不只靠颜色；空状态 = 解释"现在没有什么" + **一个可执行动作**；详情不跳无关空白页 | 入口/切换器/坞/设置段照此：没有模式时入口**不渲染**（不是渲染一个空列表）；读不到 host 状态就明说 |
| 同上 §7 | 动效克制：hover 180–240 ms、页面切换 ~470 ms、导航 ~520 ms；**减少动效要能关** | 工具台只做 120–180 ms 浅位移淡入；新增动效必须尊重 `prefers-reduced-motion` |
| 同上 §9 验收 6 条 | 去掉展示图片后层级仍成立；同类控件一致；每个按钮有真实去处；1280×800 不必整页滚；键盘焦点可见；长文本不挤坏布局 | 见 §5 的 UI 验收清单（已改写成工具台版） |
| 《项目评估与可行性分析》 | **"检查本身需要验收"**：检查器的验收与被检对象同级（他们实测出"灰度比较假通过""误报通过"） | 我们的探针必须能抓到反例：新增断言时先问"它红了会怎样"，必要时人为制造反例验证 |
| 同上 | **保留语义三分类**（像素完全不变 / 主体身份与几何不变 / 物理关系合理），不得把前者升级成后者 | 工具台对交接的承诺只到"**载荷送达并被目标模式接收**"；**不承诺**"GIR 真的照它生成了图"（那是模式自己的验收） |
| 同上 | 不填**未测得**的数字；每条结论要有证据或标注"待测" | 文档/日志里的门禁数字必须来自实跑输出；没跑的写"未跑" |
| 同上 | "双路线是最大的工程负担" → 建议**先定共享契约，再逐步共用实现**，每个核心行为**唯一事实来源** | 工具台就是"当前模式 / 上下文 / 交接 / 坞"的唯一事实来源；两个模式**不要各自再定义**一套 |
| 《定位决议（插件优先）》 | 双路线不调和、**插件优先**；独立桌面冻结 | 工具台延续同一条逻辑：**纯插件**，缺席时模式自持入口（官方壳兼容） |
| 《研究报告》§10 执行约束 | 明确写出"我们**没有**什么"；"有接口 ≠ 有能力"；不编造状态/性能/授权 | 见 §2 非目标与 §6 的"诚实清单"；坞契约存在 ≠ 每个模式都有坞视图 |
| 《研究报告》§6 | 把 LLM 当**受限解析器**，不让它宣布约束已满足 | 工具台不接受"模型宣布模式状态"；状态由模式自报，工具台如实显示 |
| 《目标文档》 | 文档要标注"这是产品目标，不是有效性的证明"；分阶段验收 | 每份新增文档开头写状态（设计 / 已实现 / 待验证）；阶段验收见 plan §0.1 |

### 3.2 明确**不能照搬**

| GIR 的条款 | 为什么不能用在工具台 |
|---|---|
| GIR 的品牌视觉（Ink/Paper 配色、酸性黄绿 `#D9FF3F`、圆角 4–8 px、67 px 应用栏、字体栈） | 工具台跑在 dsh 宿主内、被宿主皮肤重定义；**自带一套视觉家族会和皮肤打架**。视觉一致性对工具台的含义是"和宿主一致"，不是"和 GIR 一致" |
| GIR 的"六个主屏 + 三个叠层"页面清单 | 那是 GIR 的产品页面结构，不是插件门面 |
| 十层产品模型 / 计算因子 / 生图流程 | 属 GIR 模式内部，工具台不解释、不建模 |
| 移动端 390×844 适配 | 工具台是桌面壳内插件；要求是**窄窗 1280×800 可用**，不做移动端 |
| Stitch 说明里的浅灰柔和配色与旧页面结构 | 该文档已被《UI/UX 协作统一规范》v1.0 明确取代（优先级规则） |

## 4. 开发流程（改工具台 / 新增一个模式）

### 4.1 改工具台本体

1. 读契约（`plugin/workbench/README.md`）与现状表（plan §0.1），确认要动的是哪一层。
2. 改 `src/client/*`（或 `index.js` / `lib/*`）；**纯逻辑放 registry.js**（可在 node 单测），
   组件只管渲染。
3. 跑快网：`npm run test:workbench` → `npm run build:workbench` → `npm run verify:workbench-build`。
4. 跑真实 UI：`npm run verify:workbench-ui`（工具台自身）与 `npm run verify:workbench-writing`
   （写作接入，含 L1/L1.5/L2 段）；GIR 那条 `npm run verify:workbench-gir` 依赖另一个仓库，找不到会 SKIP。
5. 全链零回归：`npm run verify:writing-quick`（在 `dsh-desktop/` 下；先 `Remove-Item Env:ELECTRON_RUN_AS_NODE`）。
6. 记日志 + CHANGELOG（用户可见变化才记 CHANGELOG），署名。

> **手感没拍板的交互先走 HTML 原型**（2026-10-12 用户定的工作方式）：改 `prototypes/workbench-home/`
> 的单文件原型（零依赖，`npm run dev` 或双击即跑，不与构建/门禁挂钩），玩出手感再按上面流程落正式。
> **别从原型抄代码**——那里写死的色值只是 `--dsw-*` 令牌的取值快照；正式实现仍走令牌与 `dshWb*` 类名。
> 原型自己的落差表与踩坑见其 README。

### 4.2 新增一个模式（清单）

1. 模式自己提供：host 半（自己的 HTTP 路由，**不要**动工具台的路由）、client 半（自己的全屏浮层/视图）。
2. client 侧用**可选注入**接入：`ctx.inject(['workbench'], …)`——服务缺席时整段不执行（降级路径）。
3. `registerMode` 填：`id`（稳定）、`label`（thunk）、`order`、`mount`、可选的
   `canDeactivate`（纯判定、带 `reason`）、`onActivate/onDeactivate`、`context`、`onHandoff`、`dock`、`tile`。
4. **让位**：装了工具台时，模式自己的入口渲染 `null`；没装工具台时必须保留自持入口。
5. **状态回灌**：模式自己开关时（设置页/热键/浮钮）要回灌工具台（原因 `mode-local`），别让两套状态分叉。
6. 需要坞视图就给 `dock: { label, view }`（**运行时组件引用**，不是跨插件 import）；
   需要主屏瓷砖就给 `tile: { label, view }`——dock 是"别人当主视图时右缘的轻视图"，
   tile 是"主屏右侧瓷砖格里的主要内容窗口"，两者并立、给哪个都行；**缺 `view` 会被当成没提供**
   （主屏里退化为大按钮卡，保证模式可达——宁可退化，也不留一块点开是空白的瓷砖）。
7. 加探针段（在既有 Electron 探针里加断言，别另起一套 harness），跑门禁，记日志。

### 4.3 三条硬边界（违反会伤到用户）

- **不改内核**（`dsh-desktop/runtime/**` 与 `node_modules/@deepseek-ai/*` 一律不动）。
- **不动运行中的应用**：不杀 `DeepSeek Harness Desktop` / `electron` 进程；预览实例保持运行、由用户关窗。
- **不动别人的在飞改动**：共享工作树**禁 `git add -A`**；写作模式现在是 **submodule**，
  改它要去 `yuanzhoucanxiang/dsh-writing-mode` 仓库提交，外壳这边只更新指针。

## 5. UI/UX 规则与验收清单

**规则**（沿用宿主）：

- 样式只用 `--dsw-*` 令牌；类名 `dshWb*`；不写死颜色。
- 浮层**不占屏**：`shell.overlay` 默认 click-through，只有需要交互的元素声明 `pointer-events:auto`；
  关闭状态渲染 `null`（不是"渲染一个隐藏的大容器"）。若改用 `hidden` 属性表达隐藏，**必须**配
  `[hidden]{display:none!important}` 守卫——类里的任何显式 `display` 都会盖过 UA 的 `[hidden]` 样式
  （2026-10-12 原型首屏被"界面已关闭"遮罩糊住的实锤教训，两页同犯）。**唯一例外是主屏**：它是用户定的"一个屏幕"
  （全屏、背景不透明、盖住模式下层），打开时它就是目的地，所以 scrim 点空白**不**关闭（没有 scrim）。
- 层级：**主屏 2200 > 坞 2100 > 通知 toast 1410**；模式自己的浮层各自决定（写作 2000、GIR 60）。
  主屏打开时盖住模式与坞（关闭后原样回到，模式不卸载）；坞要能盖在模式之上、且模式可以选择
  给坞让位（`--dsh-wb-dock-width`）。
- 文案：先给结论再给原因；错误必须带**可执行出路**；不出现"失败了"这种没有出路的句子。
- 主屏**不改当前模式**：打开/关闭/在主屏里闲逛都不碰 `activeModeId`，只有点瓷砖的「进入」/按钮卡
  才走 `switchMode`（同一套关闭守卫，被拦下时主屏留在原地、不自造文案）。

**UI 验收清单**（改完自问，探针能覆盖的写进断言）：

1. 没有任何模式注册时，侧栏**没有**工具台按钮、没有主屏、坞不渲染。
2. 点入口**一律开主屏**（单模式也不直进——主屏就是目的地，不是"只有一个选项的列表"）；
   主屏打开不改 `activeModeId`。
3. 主屏结构：左列「对话」瓷砖（会话服务缺失/读不到/空列表三态**如实文字说明**，不报错不编造）、
   右侧瓷砖格——有 `tile` 的模式渲染其内容窗口 + 「进入」按钮，没有的退化为大按钮卡。
4. 切换被守卫拒绝时：不切换、不发明文案、主屏留在原地。
5. 坞：只显示"不是当前主视图"的模式；收起留 rail；展开/收起时 CSS 变量 `340px ↔ 0px`。
6. 1280×800 窄窗不出现横向滚动、长模式名/长标题不挤坏布局（`text-overflow: ellipsis`）；
   主屏在 <900px 时竖排（对话列在上、瓷砖格在下）。
7. 键盘可达：入口/主屏/坞的按钮都能 Tab 到、有可见焦点；`Esc` 关主屏；主屏里 ↑↓ 在按钮卡间循环。
8. 状态不只靠颜色：降级/错误都带文字说明。
9. 控制台零 error（探针已经在断言这条）。

## 6. 验收与诚实纪律

- **检查本身要验收**：新增断言时说明"它抓什么反例"；能用假实现制造反例的就制造一次（今天多次靠这招抓到真问题）。
- **三类证据分开**：① 单测（纯逻辑）② 真实 Electron 探针（渲染与交互）③ 实机预览（用户点验）。
  截图/GIF 只作辅助，不能替代 ②③。
- **不升级承诺**：工具台只承诺"入口/切换/上下文/交接送达/坞"，不承诺模式的领域效果。
- **诚实清单**（文档里要能一眼看到"没有"）：
  无统一数据模型 · 无模式间运行时共享 · 无真分屏 · 无跨窗口实时同步 ·
  最近打开/健康总览未实现 · `mount:'panel'` 未启用 · 模式启停探测未做 ·
  主屏对话列是 v1（只读会话标题 + 跳回，**不是真聊天窗口**）·
  写作/GIR 暂无 `tile` 内容窗口（主屏里是大按钮卡）。
- **假通过反例库**（照 GIR 的教训建）：探针 harness 回 200 + 错误封套会把"响应形状不对"记成插件崩溃；
  "切换后立刻断言"是竞态；换守卫不还原会让后续断言失去意义——都记在 `WORKLOG.md` 的「踩坑速查」。

## 7. 文档与日志义务

- 每次改动：`logs/YYYY-MM-DD.md` 追加（做了什么 / 改了哪些文件 / 结果 / 坑）+ 署名；
  用户可见变化同步 `CHANGELOG.md`；跨项目/工作区级的记到 `日志/YYYY-MM-DD.md`。
- 契约变了 → 同步 `plugin/workbench/README.md`；阶段完成了 → 同步 plan §0.1（含"没做"）；
  新模式接入 → 在对应模式的文档里写一节（写作模式在 submodule 的 `CONTRACT.md`）。
- **文档要标注状态**（设计 / 已实现 / 待验证），别让读者把设计当现状。
- 新坑先进当日日志，确认会重复咬人才进 `WORKLOG.md`「踩坑速查」。

## 8. 给下一个 agent 的启动指令（可直接复制）

```powershell
# 0) 环境：从 Electron 宿主终端（Kimi Work 等）跑门禁会继承两个变量——
#    ① ELECTRON_RUN_AS_NODE=1 必须清掉，否则 electron 以 node 模式启动、app 为 undefined；
#    ② ELECTRON_ENABLE_LOGGING=1 要带上，否则 GUI 子系统的 electron.exe 主进程日志进不了管道
#       （输出像被 npm 吞了；退出码仍准）。冷启动验收脚本已自我隔离这两条，其余探针靠自己带。
Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
$env:ELECTRON_ENABLE_LOGGING = '1'
cd "E:\Deepseek harness\dsh-desktop"

# 1) 先读三份：契约 / 现状 / 本文件
#    plugin/workbench/README.md · docs/plans/workbench-layer-v1.md（§0.1）· docs/workbench-mode-guide.md

# 2) 快网（纯 node，几十秒）
npm run test:workbench ; npm run test:mode-kit ; npm run test:writing-bridge
npm run build:workbench ; npm run build:writing ; npm run verify:workbench-build

# 3) 真实 UI（Electron 隔离窗口，不碰用户实例）
npm run verify:workbench-ui ; npm run verify:workbench-writing
npm run verify:workbench-gir      # 跨仓：找不到 GIR 客户端会 SKIP 退出 0
npm run verify:shell-shape        # 外壳形态能力（真起隔离实例 + CDP；改 main.js/preload.js 后必跑）
npm run shell-hardening-test      # 含 S9：形态通道只收枚举、只认内核页面、不污染 windowBounds

# 4) 全链零回归（较慢，期间别写文件——并行写会让门禁假红）
```
