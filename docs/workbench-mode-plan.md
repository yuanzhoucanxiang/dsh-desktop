## 0. 一句话

**工作台 = 一个把「创作模式」收进一条长条窗口的门面**：你和主 agent 的对话永远在中间那条，
需要哪个模式，就从右缘把它「拼」到旁边——拼出来的是一块独立窗口，可以再拖开、也能拖回来。

工作台**不实现任何创作能力**：写作还是写作模式、生图还是 GIR，它只负责**入口、当前是谁、上下文、拼接与交接**。

三条定位（决定了后面所有"为什么不那样做"）：

1. **纯插件、零内核改动**：跑在官方壳上也成立；壳能力缺席时降级（§3.3）。
2. **门面归插件，能力归壳**：窗口形态、开窗、置顶、关窗语义归外壳；插件只说"我要长条 / 我要拼一块"。
3. **不统一领域数据**：写作的作品库、GIR 的项目库各归各的；共享的是**句柄与现场**，不是存储。

## 1. 名词（先说清楚，否则后面对不上）

| 词 | 指什么 |
|---|---|
| **工作台** | 本次统一口径的总称。**代码与 UI 里目前仍叫「工具台」**（见 §12 改名清单） |
| **长条**（`strip`） | 进入工作台后主窗收到的形态：420 宽、贴工作区右上角、对话优先 |
| **小条**（`mini`） | 再收一档：300×168、右下角，只剩顶栏 + 一行"正在做什么" + 紧凑状态条 |
| **宽窗主屏** | 主窗是普通大小（`normal`）时的界面：左对话 + 右模式瓷砖格。**壳能力缺席时它就是正式形态**，自研壳上它是"工作区选择"这一层 |
| **接缝** | 长条右缘那条 26px 的热区；悬停弹出扇形模式图标。**长条下它是唯一的模式入口** |
| **拼接 / 分离** | 点接缝里的模式 = 给它开一块**独立窗口**贴在长条旁边；把它拖走 = 分离；拖回附近 = 吸附拼回 |
| **助手窗口** | 某些模式（写作模式）声明 `splice.assistant` 后，拼接时**额外**在长条左侧开的一块该模式的助手对话窗 |
| **模式** | 一个可被工作台接入的创作能力（写作 / GIR 生图 / 将来的导演），由各插件自己实现 |

### 1.1 形态一句话对照
| 形态 | 用户看到什么 | 什么时候出现 |
|---|---|---|
| `normal` 宽窗主屏 | 左：对话列；右：模式瓷砖格（内容窗口或大按钮卡） | 点侧栏「工具台」而壳没有长条能力；或点长条顶栏 `←` 回到这一层 |
| `strip` 长条 | 一条 420 宽的竖窗：顶栏 + 对话 + 输入 + 状态条；右缘接缝 | 自研壳上点入口的**默认**形态 |
| `mini` 小条 | 300×168：顶栏 + 一行正在做什么 + 紧凑状态条 | 点顶栏 `—` |
| 拼接（模块窗口） | 长条 + 右侧模式完整界面（+ 左侧助手窗） | 点接缝里的某个模式 |

### 2.2 明确没有（别当成有）

- **最近打开**、**健康总览**（契约留了 `recent` / `health` 字段，未实现）。
- **模式启用/禁用探测**（内核 `pluginManager` 可行性未验证）。
- **GIR 的坞视图 / 主屏 tile**（要动另一个仓库）。
- **写作模式的 `tile` 内容窗口**（宽窗主屏里目前是"进入"按钮卡）。
- **`mount:'panel'`**（与"打开会话"抢中心列的冲突未定）。
- **跨模式深耦合引用**（比方"把 GIR 的图插进文稿正文"）。
- **热键呼出工作台**（壳有热键通道，语义未接）。
- **外部工具型模式的支持**（2026-10-18 已定设计、**未实现**）：`runtime`（后端探测/启动）、
  `jobs`（长任务队列与取消）、`artifacts`（产物句柄）三个契约字段都还没被注册表接收，
  接缝与界面上也**不会**显示"后端未启动/渲染中 42%"这类状态。详见 §6.4。
- **内嵌外部 Web UI**（ComfyUI 的节点编辑器之类）：**明确不做**——模块窗口只能加载内核页，
  外部 `http` 会被壳交给系统浏览器（宪法第二十条之二，2026-10-18 拍板 A）。

## 3. 形态分工（最重要的一条规则）

### 3.1 谁来定形态

**壳是形态的唯一事实源，门面只跟随。** 页面可以申请档位（`normal` / `strip` / `mini`），
但最终显示以壳回报为准——G6 的教训就是门面自己记了一份、壳被外部改了之后对不上，接缝整块消失。

### 3.2 分工表

| 场景 | 形态 | 界面 | 模式入口 |
|---|---|---|---|
| 自研壳（有 `window.dshShell` 形态能力） | **长条** | 对话优先，**不摆瓷砖格** | **右缘接缝**（点一下 = 拼到旁边） |
| 官方壳 / 老安装包 / 探针假宿主 | 宽窗主屏 | 左对话 + 右瓷砖格 | 瓷砖「进入」（真正切模式） |
| 用户点了 `←` | 宽窗主屏 | 同上（= 原型里的"工作区选择"） | 瓷砖「进入」 |
| 用户点了 `—` | 小条 | 顶栏 + 一行 + 紧凑状态条 | 无（先回长条） |

**为什么不做"长条里也摆瓷砖格"**：420px 宽塞瓷砖必破版（用户实报过"长条内容不对"）。
瓷砖格属于宽窗，这是硬分工，不是审美偏好。

### 3.3 降级（硬约束）

- 壳能力缺席 → 需求自动退回宽窗主屏，**一个字都不发**（不发还原、不留死按钮）。
- 工作台缺席 → 各模式保留自己的入口与开关（官方壳兼容）。**这条不许破**：
  把模式绑死在自研壳上，等于在别人环境里直接不可用。

### 3.4 记住什么、不记住什么

| 东西 | 记不记 | 说明 |
|---|---|---|
| 长条拖到的位置 | **记**（按形态分别记 `workbenchShapeBounds`） | 位置越出工作区就回落到默认角 |
| 长条/小条的**形态** | **不记**：重启一律回 `normal` | 否则会一直停在条状，且窗口记忆会冻住 |
| 普通窗口的位置大小 | 记（`windowBounds`），但**形态期间不写** | 否则下次启动窗口是 420 宽 |
| 拼接宽度 | **记**（`settings.workbenchSplice`），重开时按屏幕重新夹 | 页面重载后门面还会**对账**并把它收回去 |
| **上次激活的模式** | **记**（`workbench.json` 的 `activeModeId`） | ⚠ **重启后会自动 `adopt` 它** ⇒ 上次停在写作模式，下次开应用**直接进写作台全屏**（`onActivate({reason:'restore'})`） |
| 工作台**是否开着** | **不记** | 主屏开合只活在内存里；重启后要自己点入口 |

> **"重启自动进模式"这条容易吓到人**：应用一开就是满屏写作台、看不到内核界面。
> 这是有意的（`adopt` 注释：此刻没有"正在编辑"这回事，所以**不过关闭守卫**），
> 但**文档与界面都没告诉用户**——记在 §10 待拍板里。

## 4. 主流程（用户视角，一条一条走）

> 每条都写"用户做什么 → 期望发生什么 → 失败时说什么"。**"失败时说什么"是硬要求**：
> 静默失败是最贵的 bug（G8/G9/G10 全是同一类）。

### 流程 1 · 进入工作台

1. 点侧栏底部「工具台」。
2. 自研壳：窗口**收成长条**（420 宽、贴右上角、置顶可关），对话列直接可用。
   官方壳：开宽窗主屏。
3. 只有**一个**模式都没注册时，入口**不渲染**（宁可没按钮，也不留死按钮）。

**失败时说**：形态申请失败 → 界面照常显示，不弹自造错误文案（形态是增强，不是前提）。

### 流程 2 · 在长条里跟 agent 说话

**这一块的每个控件**（自上而下，与界面顺序一致）：

| 控件 | 位置 | 行为 |
|---|---|---|
| 会话标题 | 对话区顶部 | 取会话的 `displayTitle`；「回到完整会话」在同一行**右侧**（收成小链接，不占一整行） |
| 转录气泡 | 中间主体 | **最近 6 条**；作者的话贴右，助手/活动/出错在另一侧（另一侧才显示角色名） |
| 长文折叠 | 气泡内 | 超过 **180 字**默认折三行 + 「展开全文（N 字）」；**不截断**，一个字都不丢 |
| 工具调用 | 不套气泡 | 压成一行：`⚙ 工具名 · 进行中/完成/失败`（失败带"失败"两字，不只靠颜色） |
| 流式态 | 转录末尾 | 呼吸点 + "正在生成…" + 当前 tok/s（速度无数据就不显示那一段） |
| 「+」按钮 | 输入框**左侧** | 开合一个弹层：**上传**（附件通道未接，**如实禁用**并写明原因）+ **更多工具**（= 同一批模式入口） |
| 输入框 | 中间 | `Enter` 发送、`Shift+Enter` 换行；占位文案随可用性变（不能发时写"现在还不能在这里发送"） |
| 发送钮 | 输入框**右下角**（同框） | 发送中显示「发送中…」并禁用自己（防重复发）；没有发送面时禁用 + 原因在 `title` |
| 状态条 | 输入框**下方** | `⚡ tok/s · 缓存 % · 上下文 已用/窗口` + 进度条 + 模型名 |
| 日期分隔 | 转录最上面 | v1 只写「今天」——内核 chat 节点**没有墙钟时间**，不编造历史日期 |

- 三态必须分清：**正在读**（"正在读取这条会话的内容…"）/ **空**（"还没有消息…"）/ **读不到**（"暂时读不到…"）。
  把"正在读"错报成"空"，用户会以为会话丢了。
- 正在生成时摆**流式态**，与空态**互斥**。
- 发送三态：接受 / 拒绝 / 结果不可核。**只有确认接受才清输入框**，另两种一个字都不丢，并给可执行出路。
- 「回到完整会话」：若正有模式处于当前，**先走它的关闭守卫**（被拦下就留在原地），再关主屏回内核会话。

**键盘**（长条与宽窗主屏通用）：

| 键 | 在哪 | 作用 |
|---|---|---|
| `Enter` | 输入框 | 发送 |
| `Shift+Enter` | 输入框 | 换行 |
| `Esc` | 宽窗主屏 | 关主屏 |
| `Esc` | 小条 | 等价「退出」 |
| `↑` / `↓` | 宽窗主屏的模式卡之间 | 循环移动焦点 |
| `Home` / `End` | 同上 | 跳到第一块 / 最后一块 |
| `Tab` | 全局 | 顶栏钮、接缝项、模式卡都可 Tab 到，焦点可见 |


### 流程 3 · 拼一个模式到旁边

1. 鼠标放到长条**右缘**（26px 热区，中间一道小指示条）。
2. 模式图标**以接缝为轴心按角度弹开**（中间 0°、两端 ±34°、半径 58px、逐颗错峰 45ms），
   图标与文字反向旋转保持正立；每颗下面一行「正在做什么」，右下角小圆点表示"当前/已拼接"。
3. 点一个：**给它开一块独立窗口**贴在长条右侧；模式若声明了助手窗口，长条**左侧**同时开一块助手对话。
4. 再点同一个模式 = 关掉它的窗口（含助手窗）。

**失败时说**：

- 壳不支持（老壳）→ 入口不出现，不摆一个点了没反应的图标。
- 开窗失败 → toast 说"没开成"并**保持界面原样**（不许画到窗口外）。
- 模式没有可嵌入视图 → 如实说"还没提供可嵌入视图"，不硬塞轻视图冒充完整界面。

### 流程 4 · 进入一个模式的**全屏**（与"拼到旁边"是两件事）

用户拍板 A 之后：**接缝点一下 = 拼到旁边**，**进入全屏走宽窗主屏的瓷砖「进入」**。
也就是说进全屏的路径是：点顶栏 `←` 回宽窗主屏 → 点该模式瓷砖上的「进入」。

- 进全屏 = 该模式的 `shell.overlay` 渲染出来，**覆盖整屏**（写作 `z-index:2000`、`position:fixed;inset:0`）。
- **进全屏时工作台自己会关掉**：`switchMode()` 成功后 `setOpen(false)` ⇒ 主屏渲染 `null`、
  窗口申请 `normal`（长条也一起没了）。**不是"主屏留在后面"**。
- **由此带来一个必须知道的事实**：模式浮层盖住整屏（含侧栏），所以**模式在场时点不到侧栏那个「工作台」入口**。
  要回工作台，只能走**模式自己的出口**（写作台顶栏的「退出」）。
- **退出模式后回到的是内核界面，不是工作台**：退出 = `setModeActive(false)` → 回灌 `setActive(null,'mode-local')`，
  而**没有任何地方 `setOpen(true)`** ⇒ 工作台不会自动重开。想接着用工作台得再点一次侧栏入口。
- **主屏本身不改当前模式**：在主屏里闲逛、打开/关闭主屏，都不会切模式；只有点「进入」才切。
- **为什么不能"接缝点一下直接进全屏"**：拍板 A 把接缝定了拼接。这个分工要在界面上讲清楚——
  接缝项的 `title` 已经写着"把 X 拼到右侧（要它的全屏界面就回宽窗主屏点「进入」）"。

### 流程 5 · 把拼接块拖开 / 拖回来

- 拖动**结束**才判定（拖动中判会把"手抖"当"分离"）：离目标位 ≤ **32px** 且纵向也接近 → **吸回去**；
  拖远了才算**分离**，接缝上标「已分离」，壳不再管它的位置。
- 已分离的拖回目标位附近 → **吸附拼回**（同一套阈值）。
- 分离的那块**不会**跟着工作台一起关——它的语义就是"拆下来独立活着"。
- **怎么关掉分离出去的那块**：走**接缝再点一次同一个模式**（这是目前唯一的界面内入口）；
  分离窗自己身上**没有关闭钮**（无边框窗，系统不画标题栏按钮）——见 §9 已知缺陷 D3。

### 流程 6 · 长条移动 / 变小

- 拖长条（抓顶栏那条空白）→ 还贴着的模块窗口**跟着平移**，尺寸不变。
- 长条变宽/变高 → 模块重新贴边排布（放不下就缩，**下限 220**；助手窗下限 **160**，宁可窄也不压长条）。

### 流程 7 · 回宽窗 / 退出 / 关窗（三件事别混）

| 钮 | 语义 | 会发生什么 |
|---|---|---|
| `←` | 回**宽窗主屏**（工作区选择） | 先收起拼接；窗口变宽；主屏还在，瓷砖格出现；**不退出**工作台 |
| `退出` | 退出工作台，回内核主界面 | 先收起拼接 → 有模式在场先过它的**关闭守卫**（被拦就留在原地，不自造文案）→ 还原窗口 |
| `✕` | 关这个窗口 | 走**既有**关窗语义（默认收进托盘，不退出应用）；**不改形态、不改置顶** |

> 原先 `⎋` 这个字形没人认得出（用户直接问"怎么回到主界面"），2026-10-13 已换成**文字「退出」**。
> 这是一个可复用的教训：**出口用字，不用符号**。

**三条出口的清理动作不一致**（2026-10-19 体检）：

| 出口 | 收起拼接 | 过关闭守卫 | 已拼接的模块窗口 |
|---|---|---|---|
| `退出` 钮 | ✅ `collapseSplice()` | ✅ `exitMode()` | 壳在 `normal` 时收掉**贴着的**（`closeAllModuleWindows`） |
| `←` 钮 | ✅ | ❌（故意的：不退出） | 同上 |
| **`Esc`** | ❌ **不收起** | ❌ **不过守卫** | 同上 |
| `✕` 钮 | ❌ | ❌（关窗由壳的既有语义定） | 同上 |

**`Esc` 是唯一的例外**：宽窗主屏里按 `Esc` 只做 `setOpen(false)`——不 `collapseSplice`、不 `exitMode`。
后果：门面的 `spliced` 状态没清（壳那边已经在 `normal` 时收掉窗口了），下次进工作台可能对不上。
**这条记在 §9.1 的 D4，未修。**

> **`✕` 那条要特别说清**：它只关主窗，**不会**把已经拼接的模块窗口一起带走——
> 因为壳的 `closeAllModuleWindows()` 是在 `applyWorkbenchShape('normal')` 里调的，
> 而 `✕` 走的是 `win.close()`（关窗，不改形态）。所以「关掉主窗 → 模块窗口还留在屏幕上」是这个组合的必然结果。

### 流程 8 · 小条

`—` 在 长条 ⇄ 小条 之间切。小条只有：顶栏 + 一行「当前模式 · 正在做什么」+ 紧凑状态条。
`Esc` 在小条下等价于「退出」。**小条里收掉的对话不吞字**：没发出去的正文记在内存里（刻意不落盘），展开回来还在。

### 流程 9 · 交接（模式之间递东西）

写作台的「去生图」→ 先切到 GIR（走同一套守卫）→ 把一段**不透明载荷**交给它。
如实语义：目标没有接收端 → toast 说"还没有接收端，引用没有送出去"；被守卫拦下 → 不切也不交付。

## 5. 交互细则（可调参数的单一清单）

### 5.1 窗口档位

| 档位 | 尺寸 | 位置 | 最小尺寸 |
|---|---|---|---|
| `normal` | 用户自己的窗口记忆 | 用户位置 | 980×640 |
| `strip` | 宽 **420**，高 = 工作区 × **0.86** | 工作区右上角 | 320×320 |
| `mini` | **300×168** | 工作区右下角 | 240×120 |

几何**一律主进程算**，页面只能发档位字符串——这条是安全边界，不是实现细节。

### 5.2 接缝扇形

| 参数 | 值 | 为什么是这个值 |
|---|---|---|
| 热区宽 | 26px（展开时 132px） | 展开时必须盖住扇形，否则鼠标挪过去的中途就出了热区（实报过"还没挪过去就消失"） |
| 收起宽限 | 240ms | 同上；进到图标上就取消收起 |
| 角度 | 中间 0°，两端 ±34° | 照原型；**第一颗在上、最后一颗在下**（反了会像"朝内翻"） |
| 半径 | 58px | 原型动效终点 |
| 错峰 | 45ms/颗 | 逐颗弹出手感 |
| 位置 | 没拼接贴右缘；拼接后站在**拼合处** | 原型规则："已有模式拼着时，鼠标放在拼合处" |

### 5.3 拼接与模块窗口

| 参数 | 值 | 备注 |
|---|---|---|
| 模块窗口最小/最大宽 | 280 / 900 | 壳夹住 |
| 贴边排布下限 | 220 | 放不下就缩 |
| 助手窗下限 | **160** | 长条左边常常只剩一百多像素；压着 220 会重叠在长条上 |
| 缝宽 | **-8px**（负重叠） | 视觉上拼成一体，不露缝 |
| 吸附阈值 | **32px**（横纵都判） | 手感旋钮：嫌松降到 24/16，嫌黏升到 40/48 |
| 拖动判定防抖 | 240ms | `moved` 与 `move` 双路都走同一个幂等判定 |
| 默认拼接宽 | 420 | 模式可用 `splice.width` 覆盖（写作台声明 **720**，三栏塞不进 420） |
| 降级路径宽度 | 280 – 1200（按工作区算） | 老壳走"窗内撑宽一列" |

**模块窗口的形态**：无边框、无阴影、**不可拉伸**（尺寸归壳管）、整窗跟着长条走。
拖动靠页面里的拖拽区（`-webkit-app-region: drag`），拖远即分离。

### 5.4 辅助坞（宽窗主屏专有的"同屏共存"）

**它是什么**：宽窗主屏里，右缘可以挂一块**别的模式**的轻视图——这样"我一边写、一边看生图那边的图"不用来回切。

| 项 | 行为 |
|---|---|
| 出现条件 | 有模式提供了 `dock` 视图、且**不是**当前主视图；宽窗主屏下才出现 |
| 收起态 | 右缘一条竖排 rail（竖排文字写着那个模式名），点一下展开 |
| 展开态 | 面板宽 **240–720**（默认 **340**），左缘可拖拽调宽，宽度记在 `localStorage` |
| 多模式 | 顶部变成下拉，选一个显示 |
| 让位 | 展开时把宽度写进 `--dsh-wb-dock-width`，模式可以选择给内容让位（写作台已经这么做） |
| 与互斥的关系 | 坞**不改** `activeModeId`、**不参与**关闭守卫——它是主视图的附属面 |

**三个地方刻意不显示它**（都是实机踩过）：

1. **长条 / 小条下**——坞的轨也在右缘，会和**接缝**挤在一起（用户点了 rail 上的"写作"以为点的是扇形，直接跳进了写作模式）；
2. **模块窗口里**——那块窗口本身就是"这个模式的界面"，再给它一个"切到某模式"的入口是重复；
3. **一个候选都没有时**——整块不渲染，不留一条空 rail。

### 5.5 另外两个用户可见面

**通知（toast）**：交接结果、拼接失败这类一次性结果走这里。**6 秒**自动消失，**点一下立刻关**；
挂在帧级，关掉主屏也照样计时。模式自己的错误提示也建议走它（模式不再各弹各的）。

**设置段**（内核「设置」里的一节，id `workbench`）：**当前是只读的**——它能告诉你三件事：

| 卡片 | 内容 |
|---|---|
| 说明 | 工作台是什么 + "未挂载工作台时各模式保留自己的入口" |
| 已注册的模式 | 一枚一枚的 chip，当前那个高亮；**一个都没有时如实说**"当前没有模式注册" |
| 当前模式 + 状态文件 | 当前模式名（没有就写"未进入任何模式"）；host 状态文件的 `revision`；读不到就明说 |

> ⚠ **设置段里目前没有任何可操作项**（零按钮、零输入框）——所以"置顶开关""模式启停"这类
> 都还无处可点，见 §9 已知缺陷 D1 与 §10。

### 5.6 层级与让位

- 层级（从高到低）：接缝 **2210** > 主屏 **2200** > 坞 **2100** > 通知 toast **1410**。
- **长条与小条下面不显示辅助坞**：坞的轨也在右缘，会和接缝抢同一块地方（实报过"点了 rail 以为点的是扇形"）。
- **模块窗口里不显示坞**：那块窗口本身就是"这个模式的界面"，再给一个"切到某模式"的入口是重复。
- 模式可以让位：`--dsh-wb-dock-width` / `--dsh-wb-strip-w` 由工作台写进 CSS 变量。

## 6. 状态矩阵（界面该显示什么）

### 6.1 模式 × 界面

| 模式的状态 | 接缝上的表现 | 宽窗瓷砖格里的表现 |
|---|---|---|
| 未接入 / 未加载 | 不出现 | 不出现 |
| 就绪 | 图标 + 名字 + 上下文 | 内容窗口（有 `tile`）或大按钮卡 |
| 当前（`activeModeId`） | 小圆点 + 「当前」 | 卡片标「当前」 |
| 已拼接（`anchored:true`） | 小圆点 + 「已拼接」 | —（宽窗里没有拼接） |
| 已分离（`anchored:false`） | 「已分离」（与拼接区分开） | — |
| 有未保存 / 保存中 / 体检 N | 小标记（不只靠颜色，带文字） | 同左 |
| **后端未就绪**（外部工具型，§6.4） | 小标记「Blender 未启动」 | 卡片上整块说明 + 启动钮 |
| **有任务在跑**（外部工具型） | 进度点 + 「渲染中 42%」 | 同左 |
| 上下文报不出来 | **空着**，不编造 | 空着 |

### 6.2 对话列三态

| 状态 | 文案 | 触发条件 |
|---|---|---|
| `pending` | 正在读取这条会话的内容… | 通道在，图还没送到 |
| `no-messages` | 还没有消息… | 空会话（**不是**"读不到"） |
| `none` / `no-service` | 暂时读不到… | 没有会话服务 / 没有会话 |
| 流式 | 正在生成… + 当前 tok/s | `running:true`，与空态互斥 |

### 6.3 数值缺失

三指标全都可能没有：`sessionStats` / `tokenUsage` / `contextPressure` 都是可选投影。
**算不出就写"还没数据"并说明原因，绝不拿 0 冒充"没有"**。没有会话时整条状态条不摆。

### 6.4 外部工具型模式（Blender / ComfyUI 这一类）——**设计已定，实现未接**

> **适用**：模式背后是一个**不在 dsh 进程里的工具**（Blender 的 CLI/后台、ComfyUI 的 `:8188`）。
> 写作这种纯前端模式不涉及本节。
> **状态**：契约字段与条文已定（宪法第十六～二十条之二、契约 §一·B），**工作台侧尚未实现**
> ——接缝与瓷砖目前**不会**显示下面这些东西。第一个这类模式落地时一起做。

**用户会看到的三件事**：

| 场合 | 长什么样 | 文案纪律 |
|---|---|---|
| **后端没起来** | 接缝上该模式旁一个标记「Blender 未启动」；点进去是整块说明 + **一个「启动 Blender」按钮** | 必须说**为什么**（"没找到 Blender 可执行文件" / "ComfyUI 没在 8188 上应答"）+ **下一步** |
| **任务在跑** | 接缝上「渲染中 42%」；界面里是任务行：名字 + 进度 + 已用时间 + 取消（能取消才显示） | 进度拿不到就写"进行中"而**不画假进度条**；取消不了就**不显示**取消钮 |
| **产物出来了** | 「最近产物」里一张缩略图/一条文件名，点一下跳回模式里对应位置 | 工作台只**列出与跳回**，不搬文件、不改名、不删 |

**三条体验红线**：

1. **不许"点了没反应"**：后端不可用时按钮要么可点（点了给原因），要么根本不出现——绝不置灰且无解释（G9 教训）。
2. **工作台不替你起进程**：想一键启动，是**模式自己**提供的能力；工作台只调用并如实回报成功/失败。
3. **ComfyUI 的节点图不在工作台里画**：2026-10-18 拍板 A —— 只做"任务台"形态
   （选模板 → 填参数 → 排队 → 看进度 → 收图），要拖节点就**一键用系统浏览器打开 ComfyUI 自己的界面**。
   不内嵌的根本原因：模块窗口只能加载内核页，外部 `http` 会被壳甩给系统浏览器；
   要内嵌得新增壳能力并重定 CSP/凭据边界，本轮明确不做。

**为什么值得先定设计**：这三件事原来**一条契约字段都没有**（`health` 归一到 mode 记录但 UI 拿不到、
`job/progress/cancel` 与 `artifacts.*` 零处）。等接 Blender 时才发现，就会重演"点了没反应"。

## 7. 文案与反馈纪律

1. **单一出口**：所有文案在 `plugin/workbench/src/client/copy.js`，将来本地化只改这一处。
   组件里不写散装中文。
2. **先结论再原因，必须带出路**：不出现"失败了"这种没有下一步的句子。
   例：「拼接没成功（no-splice-bridge）——窗口没变宽，界面保持原样。」
3. **禁用按钮 = 点了没反应**（G9/G10 的根因）。宁可让按钮可点、点下去如实提示原因，
   也不要把按钮置灰只把原因写在 `title` 里——没人会去悬停。
4. **状态不只靠颜色**：失败要带"失败"两个字（如工具活动行）。
5. **不编造**：上下文、健康、时间戳、模型名，拿不到就空着。
   （例：内核 chat 节点只有 `seq`，**没有墙钟时间**，所以对话里只有"今天"这种日期分隔，不编造历史时间。）
6. **窗外的桌面不是画布**：窗口边界是硬的，扇形与拼接只能收在窗内贴边。
   想要"朝窗外张开"必须新增壳能力（透明置顶辅助窗），而它的最小切片已被否掉（"这个浮标没有用就去掉"）。

## 8. 体验验收清单（改完自问，能写进探针的就写进断言）

**形态**

1. 自研壳点入口 → 申请 `strip` 且真的变成 420 宽；关闭 → 申请 `normal`；"从没收成过条就绝不发还原"。
2. 壳外部改形态（小条往返 / 程序化 set）→ 接缝与顶栏**跟着壳变**，不出现"按钮没反应"。
3. 桥缺席 → 宽窗主屏，瓷砖格在，零横向溢出。

**接缝**

4. 长条下**只有一个**模式入口（接缝），没有坞的轨。
5. 扇形：第一颗在上、正中 0°、半径恒定、逐颗错峰单调；展开时命中区覆盖扇形；离开后 240ms 内回来不收。
6. 每颗都能看到：名字、上下文、忙标记、"当前/已拼接/已分离"。

**拼接**

7. 点一下开窗（右侧），声明了助手的同时开左侧；再点关掉两块。
8. 拖 30px 松手 → 吸回；拖 200px 松手 → 标「已分离」；再拖回 → 吸附拼回。
9. 长条移动时贴着的跟着走、尺寸不变；关工作台时**分离的不关**。
10. 老壳 → 窗内撑宽降级，且**绝不**把界面画到窗口外。

**退出三钮**

11. `←` 只回宽窗、**不退出**、瓷砖格回来；`退出` 走守卫且还原窗口；`✕` 只关窗、不改形态不改置顶。

**对话与状态**

12. 三态文案准确（正在读 ≠ 空 ≠ 读不到）；流式与空态互斥。
13. 发送：只有确认接受才清输入框；拒绝/不可核时正文不丢。
14. 指标缺失写"还没数据"，不出现占位的 0。

**通用**

15. 1280×800 不出现横向滚动；长标题/长模式名截断而不挤坏布局。
16. 键盘可达：入口/顶栏/接缝/瓷砖都能 Tab 到、焦点可见；`Esc` 在主屏与小条下都有明确语义。
17. 控制台零 error。

## 9. 已知边界（当前实现的真实限制）

### 9.1 四条已知缺陷（**已确认，代码未修**，2026-10-18/19 体检发现）

> 这些不是"没做"，是**做了但用户做不到 / 点了没反应**——正是 G9 那一类。按项目所有者 2026-10-18 的决定：
> **先如实记录，代码另开一轮**。修之前，文档不许把它们写成"有"。

| 编号 | 现象 | 证据 | 影响 |
|---|---|---|---|
| **D1** | **置顶开关没有入口**：拍板过"置顶做成单独开关"，但用户**没有任何地方能关掉长条置顶** | `preload.js` 暴露了 `setWorkbenchStripOnTop`，但 `plugin/workbench/src/client/` **零调用**；`renderer/settings.html` 与 `shell-settings` 都不提它 | 长条挡住别的窗口时，用户只能忍受或退出工作台 |
| **D2** | **模块窗口里点写作台的「退出」界面不变** | 写作台 `close()` 只是 `setModeActive(false)`（失活，不关窗）；而渲染门槛是 `!active && !spliceHost && !isModuleWindow` ⇒ 模块窗里 `isModuleWindow=true`，门槛失效，**界面照常渲染** | 用户以为退出没反应。真正的出口是接缝再点一次那个模式 |
| **D3** | **分离出去的模块窗口自己没有关闭钮** | 模块窗 `frame:false` 且**没有** `titleBarOverlay` ⇒ 系统不画最小化/关闭钮；`shell:close-window` 只关**主窗**且发送方闸要求主窗（模块窗发了会被拒） | 只能靠**接缝再点一次**（但那要先把工作台找回来），或任务栏右键 / Alt+F4 |
| **D4** | **`Esc` 是一条绕过关闭守卫的退出路径**（2026-10-19 新增） | 宽窗主屏的 `onKeyDown` 里 `Esc` 只做 `setOpen(false)`；正规出口 `exitWorkbench()` 才做 `collapseSplice()` + `exitMode()`。而 `exitMode` 会先问 `canDeactivate` | 有未保存稿时按 `Esc` 照样关掉工作台（守卫没被问）；门面的 `spliced` 状态也不清。小条那条 `Esc` 反而是对的（走 `exitWorkbench`）——**同一个键在两种形态下语义不一致** |

**顺带两条不一致**（不算缺陷，但会让用户困惑）：

1. **模块窗口里点「工作台」入口**：入口没认领 `#dsh-wb-module`（`Dock.js` 认领了）⇒ 按钮照旧渲染；
   点下去 `open=true`，会把**整块主屏 overlay 渲染进那个模块窗口里**（窗里套一个全屏主屏），
   而它申请的 `strip` 会被壳的发送方闸拒掉（只认主窗）。用户看到的是"这块窗口里突然多了一整个工作台"。
2. **通知 toast 在模式浮层下会被盖住**：toast 是 `.dshWbHome` 的**子节点**（主屏开着时画在主屏之上，✅ 可见）；
   但主屏关着时只返回 toast 片段，`z-index:1410`，而写作浮层是 **2000**、坞是 **2100** ⇒
   **交接类 toast 恰好发生在这时**（交接 = 切到目标模式 ⇒ 主屏已关 + 目标模式浮层在场）⇒ 用户看不见
   "已把引用交给 GIR" 这句话。探针只判 `[data-wb-notice]` 存在与文案，没判**可见性**，所以一直是绿的。

### 9.2 硬限制（不是缺陷，是物理与取舍）

- **主窗与模块窗的无缝**：主窗已改无边框（`frame:false` + 系统三钮叠层 + 顶部拖拽带），
  模块窗无边框无阴影；但**负缝 -8px 靠几何对齐**，跨屏缩放不同时仍可能差几个像素。
- **宽度是"抢来的"**：长条固定 420，助手与模式界面按剩余空间缩；屏幕太窄时先缩模式界面，
  再到助手下限 160，**再不够就重叠**——这一档当前不处理。
- **吸附阈值与宽限是拍的值**，等着上手摸过再定稿（§5.3）。
- **多屏**：两块屏缩放不同时，窗口必须**在目标屏上直接创建**，否则会被系统按目标屏再缩放一次
  （实测请求 420×601 得 481×688）。
- **助手窗口的现场同步到了"只读"**：能看、能说，但编辑权只在写作台那块窗口。
- **置顶是 OS 位、不是自报值**：只有 `screen-saver` / `pop-up-menu` 会真正置位，且 `isAlwaysOnTop()`
  会撒谎 ⇒ 门禁读 Win32 `GWL_EXSTYLE`，不信应用自报。
- **窗口边界画不出东西**：扇形与拼接只能收在窗内贴边（§7-6）。

## 10. 待拍板（别自己定）

1. **吸附手感**的最终数字（32 是起点）。
2. **助手窗口无稿时**是否把输入框也禁用（现在只是提示）。
3. **「最近打开」与「健康总览」**要不要做、放在哪一层（契约已留字段）。
4. **宽窗主屏的去留**：现在它是"壳能力缺席时的降级形态 + `←` 的工作区选择"；
   要不要在自研壳上也保留它作为"模式总览"。
5. **模式启用/禁用**要不要在设置段里开关（依赖内核 `pluginManager` 可注入性，未验证）。
6. **外部工具型模式**（Blender / ComfyUI）：设计已定、实现未接（§6.4）。真正开工前还要定三件事——
   ① 用户能不能在工作台里**一键启动**后端（`runtime.start()` 由模式提供，但要给多显眼的入口）；
   ② ComfyUI 的**工作流模板**从哪来（模式自带 / 用户导入 / 读 ComfyUI 自己的 workflow 目录）；
   ③ 多个模式同时要 GPU 时怎么排队（工作台不代管进程 ⇒ 只能靠模式自己让路，**可能要一条新条文**）。
7. **重启后自动进上次的模式**要不要保留（§3.4）：现在开应用如果上次停在写作模式，就**直接满屏写作台**。
   要不要改成"只恢复当前模式、但不自动开全屏"，或者第一次给一句提示。
8. **`Esc` 要不要统一成"过守卫的退出"**（§9.1 D4）：现在小条下的 `Esc` 走 `exitWorkbench`（对），
   宽窗主屏下的 `Esc` 只关主屏（绕过守卫）。两者该不该一致，还是宽窗主屏本来就该"直接关"。

## 11. 添加一个新模式（写作 / GIR 之外的）

以后还会有 Blender、ComfyUI 等。**接一个新模式要守的条文在
[`docs/workbench-mode-constitution.md`](workbench-mode-constitution.md)**（十五条通用 + 五步外部工具型），
这里只给"从哪下手"的路标：

| 你的模式是什么形状 | 要读哪几条 | 典型难点 |
|---|---|---|
| **纯前端 + 内核会话**（写作、生图这类） | 第一～十五条 + 12 步清单 | 入口让位、`splice.mount` 单实例、认领模块窗口片段 |
| **外部工具型**（Blender、ComfyUI） | 上面全部 **+ 第十六～二十条之二 + 五步** | 后端探测（3s、只认指纹）、不可用界面、任务队列、产物句柄、**不内嵌外部 Web UI** |

**两条最容易踩的**（都是已经付过代价的教训）：

1. **入口唯一不是"多一个按钮也行"**：装了工作台就**必须**让出自己那套入口，否则用户看到两个入口、
   状态还会分叉（宪法第二条，写作模式 2026-10-13 实机踩到，异步注入的时机坑也记在那条里）。
2. **"点了没反应"是最高频的用户投诉**：G8/G9/G10 全是同一类。禁用按钮 = 点了没反应；
   宁可可点 + 如实提示原因（宪法第十七条、文案纪律第 3 条）。
