## 建议的验收步骤（点几下就能看到 v2 的新东西）

1. **当轮上下文**：打开 `第1章-v1.md` → 写作伙伴输入区上方应出现「参考项目备忘 · 2 条」（候选与待定问题都不算）
   → 点它展开：逐条勾选、可以看到预算说明；点右侧"参考"开关可关掉本次参考。
2. **引用身份**：选中一段文字 → 「＋ 引用稿件 / 选区」→ 引用条上会写明来源（路径 / 版本 / 选区偏移 / 是否未保存）；
   把该文件在编辑器里改一下再保存（或在另一版里打开），引用会标出「引用来自旧快照 · 重新引用」。
3. **备忘完整操作**：点「项目备忘」→ 展开那条**候选**：确认 / 编辑 / 撤回 / 历史 → 确认后它才会进入"可参考"；
   编辑已确认条目保存后，历史里能看到 before→after 并"恢复这一版"（会产生新 revision）。
4. **恢复候选**：把预览实例复制一份（或再起一个隔离实例指向同一库根）写点草稿，当前窗口的输入区会出现
   「其他窗口还有未合并的草稿」，可预览/采用（绝不自动覆盖）。
5. **会话协调**：点「会话设置 ↗」首次建立关联；重进应复用同一会话（不再新建）。
   如果在另一个窗口同时点，后到的窗口会等前一个完成（不会出现两个会话）。

## 真实模型体验（§6）——待有获授权的测试配置时执行

不索取密钥明文、不复制正式凭据到日志。三个场景（都在临时作品里做，不碰真实稿件）：

| 场景 | 操作 | 观察点 |
| --- | --- | --- |
| 1 随意谈人物动机、中途改口或暂不解决 | 在写作伙伴里聊"她为什么不拆信"，中途说"算了先不想这个" | 能顺畅交流，不强行生成任务表/落盘，不假装记住了没确认的设定 |
| 2 候选设定 → 确认 → 修改/撤回 | 让助手提一条建议 → 消息上点「记为候选」→ 确认 → 再编辑/撤回 | 只使用当前有效设定；能说明不确定性；撤回后下一轮不再带入 |
| 3 先讨论，再明确要求改稿 | 讨论后说"按这个把第 1 章改成 v2" | 走 Harness 工具与权限流程；引用正确、旧版本保留、编辑冲突不被覆盖 |
