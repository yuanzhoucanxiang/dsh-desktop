## 3. V01 · P2：保存失败没有成为可订阅的错误状态

位置：`plugin/writing-mode/src/client/entry.js:217–263`、453–460、493–497。冲突解决入口另见 140–146 行。

`subscribeDraftStatus` 目前仅触发订阅者重新读取 `conflict` 和 `dirty`；没有保存错误字段，界面也只呈现 `draftUi.conflict`。非 409 的失败虽然会调用 `notifyDraftStatus()`，仍没有可供界面显示的失败结果。恢复 flush 和「保留本地」都没有传 `onStatus`，所以原有事件回调提示也不生效。网络 rejection 则在 `await api` 处退出该保存任务，未转换为错误状态。

此外，恢复流程在实际保存之前把 dirty 清为 false；失败后没有恢复，因此不能把这个布尔值当作已落盘状态。

### 三条实测路径

| 时序 | 请求/磁盘 | 界面 |
|---|---|---|
| 恢复 GET pending 时输入 500001 字符，恢复后 flush | 生产接口实际返回 `413 draft-too-large`；磁盘仍为先前 `AFTER_REMOTE_ADOPT` | 输入仍有 500001 字符，但没有任何伙伴区错误提示 |
| 已有冲突，选择保留本地，模拟该 POST 返回 503 | 返回 `fixture-write-unavailable`；磁盘仍为 `REMOTE_RESOLVE_2`，本地 `LOCAL_RESOLVE` 尚未保存 | 只剩上一轮「请在下方选择…」旧提示，两个选择按钮已消失，没有本次保存失败说明或恢复入口 |
| 恢复结束后的 POST，模拟 fetch 网络 rejection | 新输入 `NETWORK_UNSAVED` 未落盘，磁盘仍为 `AFTER_REMOTE_TOMBSTONE` | 输入保留，没有保存失败提示 |

这三条没有证明输入当场被抹掉；风险是作者不知道恢复副本未保存，刷新/关闭后会恢复到旧稿。后续缩短输入或重新编辑能够保存，已分别验证，但不能替代失败提示与可发现的重试。

503 和网络中断由测试传输层注入，413 来自真实生产接口。冲突时序针对同一 project/window bucket 的受控第二写入者，不代表不同 windowId 的普通窗口共用文件。

### 修订要求

1. 保存状态应包含阶段与具体结果，例如 pending/saving/saved/error/conflict，以及错误信息和所属编辑版本；订阅者应能直接读取这些信息，不依赖某个调用方是否传可选回调。
2. 对 HTTP 失败、无效响应、fetch rejection/超时统一转为可见错误并保留未保存状态。成功确认对应快照后才标为保存完成；较旧请求成功不能误清更新内容的 dirty。
3. 恢复 flush、普通编辑、引用编辑、发送后的清除、解决冲突均使用同一套状态发布。失败时保留本地内容，提供合适的重试/修正入口；成功后清掉过期错误及冲突提示。
4. 413 可以明确提示缩短内容后重试，不要求对永远超限的数据无限重试。网络或临时服务失败应能在不更改作者正文的前提下重试。
