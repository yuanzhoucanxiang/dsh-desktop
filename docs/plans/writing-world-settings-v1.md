## 2. 首版用户流程

### 2.1 从讨论进入整理

1. 普通写作对话保持原状。选中一条或多条已完成消息，点击“整理为设定”。初版只允许显式选取的消息；不默默抓整个会话，也不加入未来到达的流式文字。
2. 展示来源范围：会话、消息、作者/助手身份和原文预览；允许补充“只整理夜间航行规则”等要求。范围在点击整理时冻结，项目切换后迟到结果不得应用。
3. 整理请求使用当前项目已关联的 Harness 会话和作者当前模型，通过 adapter 发送可见请求；按需创建会话沿用既有协调协议。不得临时换预设、绕过权限或覆盖作者原有输入/引用。
4. 若会话忙、请求明确拒绝，保留范围和补充要求供重试；若受理不确定，按 operationId 与新增回合核对，不自动重发。用户取消只取消本轮整理，不撤销已保存设定。
5. 只消费能关联到本次操作的最终助手输出。约定版本化结构化结果，严格校验；额外解释可以显示，格式不合格时展示原回复并允许手动整理，绝不把任意聊天自动写成候选。不要用字符串包含关系把旧消息当本轮结果。
6. AI 将作者已说清的结论、助手建议、矛盾/未决点分开；新建议标为建议。即使模型称“已确认”，应用仍只生成候选，确认只能来自作者操作。

### 2.2 候选卡片

- 字段：标题、结论、说明、边界/例外、来源；可标“仍待讨论”。空说明和空边界合法；确认时标题与结论非空。
- 操作：编辑、存为候选、确认设定、丢弃本地候选、继续讨论。修改已持久化候选时沿用冲突协议，不以“丢弃”物理删除审计记录。
- 首版逐条确认；批量确认、自动合并近似内容后置。有既存设定时可建议“更新某条/新增”，由作者显式选择，模型不能凭相似标题决定覆盖对象。
- 当前对话中候选只在本地编辑区暂存，明确显示未保存；点击“存为候选”后持久化为 proposed，刷新可恢复。离开有未保存编辑的面板须保留本窗口草稿或明确提示，不能静默丢弃。
- 保存状态沿用可订阅状态而非零散 error 字符串：保存中、已保存、未保存可重试、冲突待处理。

### 2.3 已确认设定与修订

- “项目备忘”内增加“世界观设定”分组与卡片，不另做一个全屏填表工作台。普通 fact/preference/open-question 仍正常使用。
- 修改已确认设定先保留为本地修订稿；作者点击“确认修改”才原子替换生效版本。修订期间旧确认版仍可参考，不能因开始编辑就突然消失，也不能让半成品进入上下文。
- 支持撤回、查看历史、以历史内容创建新修订；恢复不倒退 revision，不恢复陈旧 etag。
- 对话中“我改主意了”可让伙伴提出修订候选，不能据此自动写入。作者单纯聊天无须每轮审批记忆。

## 4. 数据决策：扩展项目备忘，不新增第二个权威世界库

### 4.1 权威文件与兼容

- `state/writing-memory.json` 为结构化设定的唯一权威文件，扩展现有 schema 为版本 2；普通备忘继续保留 kind/text/status/source，不凭模型输出更改既有条目。
- 设定仍为 kind=fact，新增可选 setting 对象。text 由 host 从“结论 + 有内容时的边界”确定性派生；普通备忘仍用原 text。客户端不得独立提交彼此矛盾的 text 与 setting。
- 建议字段如下；落实到 CONTRACT 时写明必填性、容量、错误码。这里是待实现结构，不代表现有 API 已支持。

```json
{
  "id": "host-generated-uuid",
  "kind": "fact",
  "status": "proposed",
  "itemRevision": 1,
  "text": "由 host 派生的结论与边界",
  "setting": {
    "type": "world",
    "title": "夜间航行",
    "conclusion": "雾季入夜后港口停止民船出航。",
    "explanation": "作者可写一段或更长的说明。",
    "boundaries": "救援船获得许可后可以出航。",
    "tags": ["港口", "雾季"],
    "sources": [
      {"sessionId": "...", "messageId": "...", "role": "author", "excerpt": "...", "snapshotHash": "..."}
    ]
  }
}
```

- document revision/etag 继续是并发写入令牌；itemRevision 用于展示和修订来源，不能替代文档级双令牌校验。ID 不由标题/路径派生，标题改名不换 ID。
- actor 是谁操作；sources 是内容出处，二者不能互相覆盖。摘录来自点击时的真实消息快照，source ID 由 adapter 提供并校验，不信任模型编造；消息不存在时显示“来源不可用”，保留已保存摘录。
- 新客户端读 schema 1 时适配普通备忘；第一次实际写入前，在锁内校验 token 并做原字节备份，再原子迁移。只读不升级。迁移失败不改变旧文件；坏 JSON/未知 schema 原件不动，报诊断。
- schema 2 必须被旧版本明确拒写；验证 v0.1.40 实际行为。老客户端面对新 host 的 setting 项不得用旧 update 请求抹掉扩展字段：要求 capability/schemaVersion，缺少时返回 upgrade-required；普通条目的兼容操作可继续。
- 降级安装不自动把 schema 2 改回 schema 1。导出普通 Markdown 可读，恢复旧备份会丢弃迁移后变更，必须明确展示差异并由作者选择，不能自动恢复。
- v1 明确技术容量：单条结构化文字合计最多 16000 Unicode 码点、来源摘录合计最多 8000 码点、最多 20 个来源；实际 HTTP body 另设 1 MiB 上限。容量冲突返回 413 并保留本地文字；这是存储上限，不是 AI 回复长度约束。普通备忘兼容既有限制。

### 4.2 历史与操作去重

- 每个确认/修订/撤回记录完整 before/after（含 setting、来源、状态、修订号），host 时间和 actor；恢复旧内容产生新 revision。
- 现有 MAX_CHANGES=800 会裁掉旧历史。首版不声称永久历史：schema 2 历史达到上限时返回 history-full、保留待保存稿，不静默丢历史；后续实现可验证的归档后才解除。现有 schema 1 已裁掉的内容不能补造。
- 所有世界观写操作携带 client 生成并在本窗口持久化的 operationId 与 requestHash；提交结果和去重记录在同一次权威文件原子写入中落盘。相同 ID/相同载荷返回原收据，相同 ID/不同载荷返回 409。
- 去重记录不得比可查询历史更早静默删除；达到配额拒绝新写入并提供可读诊断。请求 body 的字段排序不影响规范化 hash。
- 服务端先查幂等收据，再校验新操作的 revision/etag；丢失响应后的同一重试不会因旧 token 再写一遍。旧收据仅证明当时写入成功，UI 仍读取最新文档，不能倒退其他窗口的新版本。

## 5. 可读稿生成与失败恢复

- 自动生成路径固定为 `bible/世界观整理.md`；首版仅承载本功能已确认 world 条目。原有 world.md、characters.md 等不自动重写、不把全部项目目录变成受管文件。
- 生成文件标注来源版本、条目 ID/修订号和“由已确认设定生成”；内容含标题、结论、说明、边界。撤回项不留在当前确认列表，历史从备忘读取。
- 文件管理标记必须包含确切受管路径、上次生成内容 hash、source revision；放在同一权威文档的 projection 元数据中。作者创建的同名文件无受管记录时返回 projection-conflict，可另存唯一新文件，不接管。
- 确认事务：获取既有项目备忘锁 → 校验路径与双 token → 原子提交权威记录及 projection pending → 返回“设定已保存”收据 → 在同一锁序列内或随后重新持锁生成投影。生成操作必须重新读当前 revision，不拿排队旧快照覆盖新内容。
- 投影失败返回/展示“设定已保存，可读稿待同步”，不能显示全成功，也不能把已提交设定假装回滚；重试只同步投影，不重新新增设定。
- 写可读稿前校验文件 realpath/父目录及旧 hash，再原子替换；最终 hash 对比后把投影标记设为 synced。投影元数据更新也遵守 revision/etag 协议，向客户端回传最新 token；并发变化宁可 409，不能绕开锁补写。
- 进程在“权威记录成功、投影未写/写完未标记”时退出：下次检查 pending，读取最新权威快照；若目标 hash 等于预期生成结果，补齐状态即可。否则只在目标仍等于上次受管 hash 时重试；外部编辑则冲突，不静默覆盖。
- 生成稿被外部编辑：给查看差异、保留手稿/另存生成稿、将手工内容交给整理形成新候选的入口。外部编辑不直接成为确认设定；选项取消时保留两端内容。
- 统一锁顺序，不在持锁期间等待模型/用户/网络。读写均校验库根、项目归属、state 和 bible 的 junction/symlink 边界。现有路径检查不是任意外部进程的完整沙箱，不夸大保证。
- 原子文件替换 + hash 检查不等于跨外部编辑器事务隔离：写前保存被替换原字节到可恢复副本，失败不删；覆盖竞争后的版本仍能取回。测试明确区分应用窗口协调与外部写者竞态。

## 6. 待新增的接口契约

以下 route 为方案建议，实施在 CONTRACT 中定稿，不能文档先冒充已存在。

| 操作 | 接口建议 | 约束 |
|---|---|---|
| 能力与数据读取 | 扩展 GET memory | schemaVersion、capabilities、items、history、projection 状态、revision/etag；保持旧字段 |
| 保存候选 | POST memory，op=save-setting-candidate | operationId、requestHash、双 token、来源快照；固定 proposed |
| 确认/修订 | POST memory，op=confirm-setting | itemId 或新增、双 token、完整字段、明确的作者动作；状态 confirmed |
| 撤回/历史恢复 | 扩展既有操作 | 设置字段完整保留；来源、修订号、审计与去重一起校验 |
| 查询受理结果 | GET memory-operation | project + operationId，返回收据/未找到；不触发重写 |
| 重试生成稿 | POST setting-projection | 固定受管目标、当前 revision/etag；不允许任意目标路径 |

统一错误：400 输入非法；403 路径/权限拒绝；409 版本/来源目标/投影/operationId 冲突；413 技术容量；428 缺双 token；5xx IO/损坏诊断。与既有 route 错误码不一致时保持旧行为、单列新码，不全局破坏兼容。

来源正文和模型输出均为数据，不能作为文件路径或 host 操作命令。抽取结果必须过 allowlist schema；任何模型返回的 confirmed/targetPath/actor 都不能越过作者操作与 host 校验。

## 7. 上下文与模型整理约定

- 新设定自动注入只取 confirmed 的“结论 + 边界”，作为不可拆分的一个预算单元；explanation、source excerpt 不进入默认 preparedTurn。仍是现有默认 6000 Unicode 码点预算，不是 token；作者正文与显式引用保持完整。
- 本轮排除优先于固定优先；超过预算时整条省略并显示原因，不能截掉边界。自动选不到的内容不声称 AI 已看到。
- 首版相关性不额外调用模型：作者固定优先；其余 world 设定依据当轮作者文字/引用与标题、标签的规范化精确匹配排序（NFKC、大小写归一，空关键词忽略、同分按稳定 ID）；无匹配按既有稳定顺序补齐。普通备忘默认顺序保持兼容，所有设定共享同一总预算，避免重复注入。
- 这只是可解释的初始排序，不宣称语义检索。字符重叠/没有命中时不隐藏所有设定；人工选择始终优先。
- UI 和发送共用同一纯选择函数；发送前重新读取并冻结来源 revision、actual selected、omissions。若预览后文档变化，发送结果按最新读取结果展示，不拿旧预览当证据。
- 需要完整说明时，伙伴通过既有原生工具按需读当前生成稿/权威设定。投影 pending/conflict 时提供明确的新旧状态，不能把旧生成稿标为最新；没有可用的权威详情读取能力时明示限制，不编造工具 API。
- 原生会话历史和压缩可能仍保留撤回前文字；“撤回”保证不再自动注入旧条目，不保证模型遗忘。设定变化后的上下文应注明当前版本优先，真实模型测试检查其实际行为。
- 整理提示要求保留分歧、不捏造作者同意、引用真实来源；工具权限仍由 Harness 处理。显式整理请求不得附加默认文件写入指令；自由聊天的原生工具能力不被全局禁用。

## 9. 验收矩阵（每项必须填写证据）

统一结果：PASS / FAIL / NOT_RUN / BLOCKED；禁止把缺少环境写成 PASS。每行附命令或真实操作、源码 SHA、产物 hash（适用时）、证据路径与实际观察。

| ID | 场景与正向断言 | 层级 |
|---|---|---|
| W00 | H3/H4：非空无 project.md 目录不被覆盖；点段/保留名不落库根；合法新目录成功 | host + UI |

## 10. 交回物与复核方式

在 `docs/audits/writing-world-settings/<实施日期>/` 交回：

1. handoff.md：基线与最终 SHA、提交顺序、文件边界、启动/复跑命令、未完成事项。
2. acceptance.md：W00–W25 逐条状态、实际证据；不使用“总体全过”遮住未跑项。
3. known-issues.md：限制、迁移/降级风险、历史容量、投影冲突、模型输出失败与环境缺项。
4. protocol.md：落实后的 schema、接口、错误码、状态图、幂等/锁顺序、迁移和故障恢复说明；同步 CONTRACT。
5. 测试输出与必要截图、真实模型转录（去除凭据）、测试稿件前后副本、包/profile manifest 哈希与版本身份。
6. preview.md：TEMP 下产物和独立 userData 路径、启动命令、PID、六步试用：讨论→整理→编辑确认→查看可读稿→改设定再聊→刷新/另一窗口验证。

复核顺序：先静态契约和迁移 → 独立负向探针（重复写、并发、崩溃点、手稿覆盖、来源混淆）→ 原基线 → 真包 → 真实模型体验。不得只审实现者自己的正向测试。

完成条件：所有必做工程项通过；真实场景逐项有结果并解决阻塞问题；可见预览可使用；日志/策划案/契约与实现一致。仍有未跑项就明确交 PARTIAL，不把实现进度写成已发布。
